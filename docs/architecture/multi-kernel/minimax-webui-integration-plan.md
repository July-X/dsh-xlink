# MiniMax Code 接入 dsh-xlink：统一工作台开发计划

状态：重新规划，尚未完成。更新：2026-11-07。开发位置：独立 worktree，分支 `codex/minimax-webui`。

本文整份替换此前的独立 MiniMax 管理页方案。旧方案可从 Git 历史查看；本文件是后续实现和验收的唯一计划入口。现有未提交代码和测试结果只作为开发资料，是否交付以本计划为准。

## 1. 目标与产品边界

dsh-xlink 仍是一套桌面外壳。管理窗口顶部提供 **DSH / MiniMax** 两个 tab，用户在同一个导航和已有页面中管理当前选中的内核。切换 tab 只切换管理上下文，不启动、停止或切换另一个工作台的会话；两种工作台可以同时运行。

- **按内核区分**：安装包及版本、安装位置、实例、进程、端口、工作台状态、账号、会话和内核特有的信息。
- **尽量共用**：概览和内核版本页面框架、插件与技能管理、记忆管理、通用设置、日志、进度、通知及既有组件和服务。共享能力是否对当前内核生效，以真实接线与能力状态为准。
- **各自适配**：npm 包和启动参数、插件加载协议、技能发现方式、记忆注入、窗口和主题信号。差异放在现有适配器和具体服务边界，避免复制一套管理系统。
- **浏览器宿主**：外壳负责让 MiniMax WebUI 正常登录、渲染、导航和交互，并维护窗口、档案和进程；MiniMax 自身的对话及业务行为由已安装的 WebUI 实现。不能从首页渲染成功推断所有浏览器功能均已通过。

Windows 先开发验证；Intel macOS 和两平台同一候选提交的安装包验收是发布候选门槛。实验入口在完成必测项之前不进入常规发布。

## 3. 页面与交互规划

### 3.1 全局切换与导航

管理窗口顶部始终显示当前内核 tab；选中项有文本、选中态和键盘可达的焦点态。切换后保留当前导航页，在该页刷新相应内核的数据；不存在该内核实例时显示可操作的未安装状态。壳模式各自记住选择，现有 DSH 用户首次进入仍落在 DSH。

```text
                     [ DSH ] [ MiniMax ]
工作台  概览          当前内核状态、启动 / 打开 / 停止
        用量分析      当前内核数据和适用的共享信息
资源    内核版本      当前内核的版本、安装与运行环境
        插件          同一管理页：来源、兼容性、当前内核接线
        技能          同一中央技能库：启用状态、当前内核生效状态
        记忆          同一管理页：来源、适用范围、授权与生效状态
系统    设置          外壳共用设置 + 当前内核专属设置
```

不新增侧栏「MiniMax Code」入口或另一套 MiniMax 记忆页面。当前工作台独立 WebView 是内容窗口，管理窗口和导航仍共用。组件只读状态、调用 store 动作；IPC 仍经 `ui/src/shell/bridge.js`。

### 3.2 各页面调整

| 页面 | 共用内容 | 按选中内核调整 |
| --- | --- | --- |
| 概览 | 页面结构、状态卡、启动进度、错误与日志入口 | 内核名称、版本、运行状态、启动/打开/停止动作及实际支持的数据。没有数据时显示原因，不用 DSH 数值填充 MiniMax。 |
| 内核版本 | 已安装/可安装列表、安装进度、错误与更新交互 | DSH 与 MiniMax 使用各自包、版本列表、安装目录、原生依赖检查和启动要求；同一页面内显示当前对象。外部已安装包可检测并只读使用，也应提供壳内安装入口。 |
| 插件 | 同一个插件列表、来源管理、校验、安装/卸载、更新和通用设置 | 每项展示当前内核兼容性、启用及接线结果；DSH 专用插件标明不支持。Ponytail、记忆、官网引用等分别实现并验证各自的 MiniMax 适配，不能把“已下载”显示为“已生效”。 |
| 技能 | 同一个中央库、搜索、安装、启停、更新与冲突提示 | 显示当前内核是否可发现及生效；MiniMax 自有的用户/项目技能来源须可区分。启停共享技能后，两内核的实际生效时机须明确。 |
| 记忆 | 同一记忆管理页、记录编辑、检索、审核、删除和授权交互 | 显示来源、适用范围和当前内核是否可使用；支持把经批准的通用或同项目记忆明确用于两个内核，并保留仅适用于原实例的记录。未经接线时明确显示待接入。 |
| 设置 | 主题、外壳自启、日志等外壳级选项使用同一份 | 端口、内核运行配置和仅某一内核支持的选项按内核显示；通知等混合选项按真实作用范围标注。切 tab 不能静默覆盖另一内核的值。 |
| 用量分析 | 复用页面、图表及已有独立外部来源许可 | 按当前内核显示能可靠获取的数据；来源和统计口径明确区分，缺少来源时显示不可用。 |
| 官方对话与日志 | 复用现有独立窗口和入口 | 官网对话登录及其引用适配与本地 MiniMax 登录分开；日志按实际内核/实例筛选，保留外壳日志。 |

沿用现有窗口规格和样式 token；长名称、窄内容区、键盘、屏幕阅读器和浅色/深色/系统主题均需验证。错误显示原因、下一步及可用的日志入口。启动、安装、停止等动作沿用现有 loading 与长任务进度规则。

## 4. 共享模型和内核适配

### 4.1 当前目标和并发

1. 在现有内核族/实例记录上确定当前操作目标，前后端传递或解析经过验证的 `family + instance_id`。复用既有注册表及切换逻辑，不以 UI 标签或路径字符串猜测目标。
2. 先盘点所有依赖 DSH 默认实例、缓存 `AppState.data_dir` 或固定 profile 的生产调用链。针对页面请求接入正确目标；保留现有 DSH 后台、通知、迁移和退出语义，不能简单把全局默认实例改成当前 tab。
3. 读写操作在开始时绑定目标。长任务完成前切 tab，不得把结果写到新选中的内核；过期响应不得覆盖当前页面。无法安全并发的动作禁用相应切换并解释原因。
4. 统一状态与能力来源：页面通过已有 store 和后端返回的真实状态渲染；内核差异集中在现有适配器与服务。只为实际差异扩展接口，避免重复维护两套能力真值。
5. dev / release 各自保留实例、设置和插件中央库边界；共享技能沿用现有跨壳规则。不得让 tab 选择修改注册表的共享默认指针或改变另一壳的数据。

### 4.2 安装和运行

- 内核版本页按族选择 npm 包与版本。DSH 沿用现有安装流程；MiniMax 使用 `@minimax-webui/minimax-code` 和其实际发布的版本、入口及 Node 要求。包不同不等于必须改变用户的 registry 设置。
- 复用现有取源、进度、摘要校验、失败清理及日志；缺少可用摘要时拒绝安装。安装 stub 与依赖树只能走仓库允许的安装路径，不修改已安装内核的 `node_modules`。外部安装目录只读；卸载已有安装目录仅在用户明确操作时执行。
- MiniMax 首轮候选为 `0.1.7` / Node `26.12.0`。用选定 Node 实际检查 SQLite 与终端原生依赖，版本满足 engines 不等于原生模块可用。受管安装在 Windows 与 Intel Mac 分别验证脚本许可、重试、失败回退和升级。
- 每个内核使用独立实例数据、浏览器档案、进程和端口；MiniMax WebUI 与 Mini App 使用两个回环端口。账号、会话和 MiniMax Desktop/CLI 数据不自动合并或迁移。
- 启动要验证本轮进程及监听归属、首页就绪和必要连接；停止优先正常退出，确认所属进程树和端口后清理记录。失败保留证据和重试入口；不凭 PID 或端口单独终止进程。壳退出沿用现有确认与原生兜底，任何工作台停止失败均保留壳。
- 真实运行严格使用临时 `DSH_XLINK_HOME`、编译期 `app.appDirectoriesOverride`、独立 `DSH_XLINK_CHANNEL_SUFFIX` 和浏览器档案；证据放在本轮临时 home 之外，日志不得记录登录凭据或带令牌的 URL。

### 4.3 插件、技能与记忆

- **插件**：复用下载校验、中央库管理、资源物化和现有页面；按具体内核协议实现物化与加载。优先接通内置 Ponytail、记忆、官网引用，再按实际兼容性管理第三方插件。OpenAI 登录只在 MiniMax 提供可验证的接入方式和相应授权时标记可用。每项区分未安装、已安装待接线、已启用、待重启和失败。
- **技能**：以现有中央库及启用状态为权威；根据 MiniMax 的实际扫描规则生成实例可读视图。目录技能、平铺 Markdown、Windows junction、macOS 链接、文件冲突和运行中变更分别验证；不得覆盖或删除未经归属确认的用户文件。启用/停用和更新失败须能恢复，不影响 DSH。
- **记忆**：复用现有页面、记录与检索逻辑、审核、并发保护和授权。记录有清晰的来源及适用范围；共享记录在一个权威位置维护，不能靠复制两份造成编辑、删除或撤销不一致。保留现有实例记忆和来源；把已有记录用于另一内核须有明确的范围与授权，不因切 tab 自动迁移、合并或暴露。项目记忆按现有项目归一化规则匹配。
- **记忆运行接线**：根据 MiniMax 原生 hook/MCP 能力，将当前实例、会话和项目映射到已有受限记忆服务；凭据只授予所需权限，不把完整管理桥令牌交给 WebUI 或 hook。真实模型请求中确认内容已送达，才标记注入可用；自动提取、工具、效果统计分别验证并如实展示状态。
- 能力不兼容、冲突或验证不足时在共用页面显示原因和下一步，保留原数据，不将 DSH 能力误标为 MiniMax 已支持。

### 4.4 窗口与浏览器

复用现有窗口、弹窗、主题和托盘基础设施。MiniMax 在独立窗口加载本轮可信回环地址；登录弹窗继承该实例档案并返回原工作台。页面不拥有壳管理命令权限，外链、导航和回调按实际需要设置边界。

验证登录、页面渲染、点击与键盘输入、文件/目录选择、下载、剪贴板、同源 WebSocket、授权弹窗及关闭/重开后的登录与会话恢复。主题按当前窗口内容选择作用域，不用应用级主题改变另一窗口。实际 MiniMax 页面需要的浏览器能力若不受平台 WebView 支持，记录复现和替代方案，不声称已完整支持。

## 5. 已有工作如何处理

- **保留并重新接线**：隔离探针、版本/原生依赖检查、受控启动、Windows 独立 Job、正常停止、回环端口归属、独立 WebView 档案、授权弹窗和脱敏日志等可复用成果；以新调用链重新验证。
- **收敛**：当前未提交的独立 MiniMax 侧栏入口、`McodePanel.vue`、`McodeMemory.vue` 及其专用管理 store/命令属于实验实现，不作为最终产品结构；将可复用逻辑整合到现有概览、版本、插件、技能和记忆页面，再移除重复入口。不能把实验记忆页面当作记忆注入完成。
- **保留待审草稿**：尚未进入生产调用链的技能对账、MiniMax 记忆 hook 和受限桥先保留为工作区草稿，核对与现有共享服务的重合部分后再接入；不得因模拟测试通过就声明能力完成。
- **继续解决已知限制**：Windows 在候选组合下存在 SQLite 备份长路径限制；失去进程句柄后的旧记录当前缺少可用的自动恢复；建窗等待、顶层导航策略及授权弹窗收尾仍需处理。保留失败与成功证据，不自动清理用户数据。

## 6. 实施顺序与分批提交

每一批只提交本阶段相关文件，先做定向验证并检查暂存内容；本地提交，不推送。若发现依赖未完成，保留未完成状态，不将半成品包装为已通过。

1. **目标选择与统一外壳**：盘点默认实例调用方，恢复两个内核 tab 和实例解析；消除独立侧栏入口；补切换、迟到响应、未安装状态和 DSH 回归测试。
2. **概览与安装**：共用现有概览、内核版本页和进度；按内核路由安装、版本、状态和启停；完成 MiniMax 受管安装与外部安装检测，验证失败与回退。
3. **窗口、进程和退出**：将已验证的 MiniMax 启停及窗口接入统一动作，完善浏览器能力、恢复和异常退出；验证双内核同时运行、分别停止和托盘退出。
4. **共享技能**：复用中央库和管理页，完成 MiniMax 视图、冲突与启停/更新接线；验证两内核真实发现和 DSH 回归。
5. **共享插件**：复用中央库和管理页，按插件逐项完成 MiniMax 协议适配、兼容状态、启停和升级；分别提交可独立验证的内置适配。
6. **共享记忆**：复用管理页与后端；实现适用范围、授权及 MiniMax 实际注入，验证共享记录编辑、删除、撤销、项目匹配与跨实例隔离。
7. **设置、用量与文档**：收敛共用/专属设置和数据展示，同步 README、架构、磁盘布局及文档索引。
8. **候选验收**：用同一候选提交构建 Windows 和 Intel macOS 安装包，按下表记录结果；发布前按仓库规则执行完整门禁。

## 7. 验收标准

每项按 Windows、Intel macOS 分别记 `pass`、`fail`、`blocked` 或 `not_run`，记录候选提交、安装产物摘要、系统/WebView/Node/包版本、步骤与证据。自动测试和受控夹具不能代替真实 WebUI 或安装版验证。

| 编号 | 验收场景 | 通过标准 |
| --- | --- | --- |
| A01 | 未安装与受管安装 | 两个 tab 可见；内核版本页展示对应包和版本；下载校验、原生依赖、安装失败和重试正确，外部包保持只读。 |
| A02 | tab 与页面 | 切换保留当前页面并刷新当前对象；未安装和错误可恢复；旧请求与长任务不会覆盖或写入另一目标。 |
| A03 | 两个工作台 | 两内核可同时启动、开窗、关闭窗口和分别停止；进程、端口、实例数据和日志归属正确。 |
| A04 | 浏览器宿主 | 壳内完成登录、首页渲染和基本点击/输入，验证目录选择、下载、剪贴板、WebSocket、弹窗与回调；重开窗口及重启服务后登录和会话恢复。MiniMax 审批业务不作为单独的壳功能验收目标。 |
| A05 | 共享技能 | 同一中央技能在两个内核按启用状态可发现；禁用、更新、冲突与用户自有技能均按来源和归属处理；两平台路径含空格与中文。 |
| A06 | 共享插件 | 同一页面可管理来源与当前内核接线；不兼容插件准确提示。已声明支持的内置能力在真实 MiniMax 调用链中启停和生效，DSH 不受影响。 |
| A07 | 共享记忆 | 同一页面可管理原有和明确共享的记录；两个内核各自只获取已授权且适用的内容。编辑、删除、撤销、项目匹配和并发写入一致；真实模型请求证实注入。 |
| A08 | 设置与用量 | 外壳共用设置一致，内核专属设置不串写；用量按真实来源标注，外部工具用量许可维持独立。 |
| A09 | 隔离与安全 | dev/release、两内核账号、进程和浏览器档案隔离；陌生端口/进程不被收养或终止；日志无凭据；受限页面无法调用壳管理命令。 |
| A10 | 关闭与异常恢复 | 关工作台只关窗口；托盘退出认领、取消、正常退出及原生兜底正确；启动竞争、意外退出和停止失败可诊断且不误删数据。 |
| A11 | DSH 和 UI 回归 | DSH 旧配置、安装、工作台、插件、技能、记忆、设置、用量、官方对话与退出正常；键盘、收起侧栏、长路径及三种主题可用。 |

开发期运行命中的 Rust/前端测试、`npm run build:ui`、`check:invariants`、`check:duplicates` 和必要编译检查；文档链接及锚点在改动后检查。验证和隔离细则见 [开发验证](../../operations/development.md)，内核与安装边界见 [运行时边界](../runtime-boundaries.md)，窗口和退出契约见 [窗口架构](../window-architecture.md)。
