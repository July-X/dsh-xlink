# MiniMax Code 接入 dsh-xlink：统一工作台开发计划

状态：实验接入已实现，验收尚未完成。更新：2026-11-07。开发阶段使用独立 worktree 和 `codex/minimax-webui` 分支；接手开发先看[交接记录](minimax-webui-handoff-2026-11-07.md)。

开发进度：实验构建已接入内核切换器（页头分段控件）、MiniMax 概览和版本页，以及共用技能、插件、记忆和设置页面；受管安装、Windows 新实例技能同步、Ponytail 接线及逐条授权的记忆桥已有开发实现。Windows 隔离开发构建已验证双内核运行及分别停止。

2026-11-07 续：**共享能力不再只挂在 Windows 上**。Unix 侧补了 MiniMax 子进程树跟踪（`kernel/mcode_tree.rs`），macOS 的启动禁令随之撤掉；技能生命周期锁、Ponytail 插件与记忆桥改成跨平台实现（Unix 走 `flock` 与 0600 凭据写、排他改名收敛到 `shell/atomic_write.rs` 一份）。Intel macOS 上第一次跑出真实证据：隔离生产链 smoke 通过（真实壳 + 真实 `@minimax-webui/minimax-code@0.1.7`：检测、启动、双回环端口归属、独立窗口、切 tab 服务仍在、停止后端口释放）。真实登录、目录选择与下载等浏览器能力仍未验收。

本文整份替换此前的独立 MiniMax 管理页方案。旧方案可从 Git 历史查看；本文件是后续实现和验收的唯一计划入口。现有未提交代码和测试结果只作为开发资料，是否交付以本计划为准。

## 1. 目标与产品边界

dsh-xlink 仍是一套桌面外壳。管理窗口在概览、内核版本、记忆三个与内核指向性绑定的页面页头提供 **DSH / MiniMax** 内核切换器（分段控件），用户在同一个导航和已有页面中管理当前选中的内核；用量分析、插件、技能、设置是公共页，不读内核状态。切换内核只切换管理上下文，不启动、停止或切换另一个工作台的会话；两种内核允许同时启用并并行运行，各自停止时只影响自身。短暂的启动操作锁不得演变成整个运行期互斥。

- **按内核区分**：安装包及版本、安装位置、实例、进程、端口、工作台状态、账号、会话和内核特有的信息。
- **尽量共用**：概览和内核版本页面框架、插件与技能管理、记忆管理、通用设置、日志、进度、通知及既有组件和服务。共享能力是否对当前内核生效，以真实接线与能力状态为准。
- **各自适配**：npm 包和启动参数、插件加载协议、技能发现方式、记忆注入、窗口和主题信号。差异放在现有适配器和具体服务边界，避免复制一套管理系统。
- **浏览器宿主**：外壳负责让 MiniMax WebUI 正常登录、渲染、导航和交互，并维护窗口、档案和进程；MiniMax 自身的对话及业务行为由已安装的 WebUI 实现。不能从首页渲染成功推断所有浏览器功能均已通过。

本阶段聚焦 Windows 开发与验证；其他平台由用户单独测试，不作为当前 Windows 开发的前置条件。实验入口在完成相应必测项之前不进入常规发布。

## 3. 页面与交互规划

### 3.1 全局切换与导航

管理窗口**不再有顶部的内核族页签**（2026-11-07 用户要求）：内核维度是「与内核指向性绑定的控件」的属性，不是整页的属性。切换器（分段控件，DSH / MiniMax）只出现在三个绑定页的页头——概览、内核版本、记忆；用量分析、插件、技能、设置这些页的数据与内核无关，不读内核状态。切换后保留当前导航页，在该页刷新相应内核的数据；内核选择每页各一份（`pageFamilies`），三个绑定页互不影响；落盘仍只有一份 `kernel-selection.json`，只当启动时给三页播的种子。不存在该内核实例时显示可操作的未安装状态，现有 DSH 用户首次进入仍落在 DSH。MiniMax 那一路是实验入口，切换器上挂一枚「实验」徽记，别让人把它当成已交付的内核。

```text
工作台  概览          当前内核状态、启动 / 打开 / 停止（页头有内核切换器）
        用量分析      套餐额度与模型用量（公共页，不随内核切换）
资源    内核版本      当前内核的版本、安装与运行环境（页头有内核切换器）
        插件          公共页：DSH 与 MiniMax 两块并列
        技能          公共页：同一中央技能库，MiniMax 同步状态恒显
        记忆          同一管理页：来源、适用范围、授权与生效状态（页头有内核切换器）
系统    设置          公共页：外壳共用设置 + 两套端口并排
```

不新增侧栏「MiniMax Code」入口或另一套 MiniMax 记忆页面。当前工作台独立 WebView 是内容窗口，管理窗口和导航仍共用。组件只读状态、调用 store 动作；IPC 仍经 `ui/src/shell/bridge.js`。

## 4. 共享模型和内核适配

### 4.1 当前目标和并发

1. 在现有内核族/实例记录上确定当前操作目标，前后端传递或解析经过验证的 `family + instance_id`。复用既有注册表及切换逻辑，不以 UI 标签或路径字符串猜测目标。
2. 先盘点所有依赖 DSH 默认实例、缓存 `AppState.data_dir` 或固定 profile 的生产调用链。针对页面请求接入正确目标；保留现有 DSH 后台、通知、迁移和退出语义，不能简单把全局默认实例改成当前选中的内核。
3. 读写操作在开始时绑定目标。长任务完成前切内核，不得把结果写到新选中的内核；过期响应不得覆盖当前页面。无法安全并发的动作禁用相应切换并解释原因。
4. 统一状态与能力来源：页面通过已有 store 和后端返回的真实状态渲染；内核差异集中在现有适配器与服务。只为实际差异扩展接口，避免重复维护两套能力真值。
5. dev / release 各自保留实例、设置和插件中央库边界；共享技能沿用现有跨壳规则。不得让内核切换器的选择修改注册表的共享默认指针或改变另一壳的数据。

### 4.2 安装和运行

- 内核版本页按族选择 npm 包与版本。DSH 沿用现有安装流程；MiniMax 使用 `@minimax-webui/minimax-code` 和其实际发布的版本、入口及 Node 要求。包不同不等于必须改变用户的 registry 设置。
- 复用现有取源、进度、摘要校验、失败清理及日志；缺少可用摘要时拒绝安装。安装 stub 与依赖树只能走仓库允许的安装路径，不修改已安装内核的 `node_modules`。外部安装目录只读；卸载已有安装目录仅在用户明确操作时执行。
- MiniMax 首轮候选为 `0.1.7` / Node `26.12.0`。用选定 Node 实际检查 SQLite 与终端原生依赖，版本满足 engines 不等于原生模块可用。受管安装在 Windows 与 Intel Mac 分别验证脚本许可、重试、失败回退和升级。
- 当前实现仅允许安装和启动 `0.1.7`；版本页可列出受管安装和 npm 发布版本，其余版本只展示待验证，不按通用 semver 推断兼容。新下载的包须核验摘要、包身份及原生依赖；复用已有目录时检查包身份及原生依赖，不能覆盖已有版本目录。
- 每个内核使用独立实例数据、浏览器档案、进程和端口；MiniMax WebUI 与 Mini App 使用两个回环端口。账号、会话和 MiniMax Desktop/CLI 数据不自动合并或迁移。
- 启动要验证本轮进程及监听归属、首页就绪和必要连接；停止优先正常退出，确认所属进程树和端口后清理记录。失败保留证据和重试入口；不凭 PID 或端口单独终止进程。壳退出沿用现有确认与原生兜底，任何工作台停止失败均保留壳。
- 真实运行严格使用临时 `DSH_XLINK_HOME`、编译期 `app.appDirectoriesOverride`、独立 `DSH_XLINK_CHANNEL_SUFFIX` 和浏览器档案；证据放在本轮临时 home 之外，日志不得记录登录凭据或带令牌的 URL。

### 4.3 插件、技能与记忆

- **插件**：复用下载校验、中央库管理、资源物化和现有页面；按具体内核协议实现物化与加载。优先接通内置 Ponytail、记忆、官网引用，再按实际兼容性管理第三方插件。OpenAI 登录只在 MiniMax 提供可验证的接入方式和相应授权时标记可用。每项区分未安装、已安装待接线、已启用、待重启和失败。
- **技能**：以现有中央库及启用状态为权威；根据 MiniMax 的实际扫描规则生成实例可读视图。目录技能、平铺 Markdown、Windows junction、macOS 链接、文件冲突和运行中变更分别验证；不得覆盖或删除未经归属确认的用户文件。启用/停用和更新失败须能恢复，不影响 DSH。
- **记忆**：复用现有页面、记录与检索逻辑、审核、并发保护和授权。记录有清晰的来源及适用范围；共享记录在一个权威位置维护，不能靠复制两份造成编辑、删除或撤销不一致。保留现有实例记忆和来源；把已有记录用于另一内核须有明确的范围与授权，不因切换内核自动迁移、合并或暴露。项目记忆按现有项目归一化规则匹配。
- **记忆运行接线**：根据 MiniMax 原生 hook/MCP 能力，将当前实例、会话和项目映射到已有受限记忆服务；凭据只授予所需权限，不把完整管理桥令牌交给 WebUI 或 hook。真实模型请求中确认内容已送达，才标记注入可用；自动提取、工具、效果统计分别验证并如实展示状态。
- **授权与在途响应**：记忆内容写入（包括编辑、删除、停用和范围变更）、逐条撤销授权及关闭目标 MiniMax 的记忆许可，与桥响应写出通过同一把可重入系统锁串行化。已经写出的响应不能撤回；这些生产调用链和时序仍需集中验证。
- 能力不兼容、冲突或验证不足时在共用页面显示原因和下一步，保留原数据，不将 DSH 能力误标为 MiniMax 已支持。

### 4.4 窗口与浏览器

复用现有窗口、弹窗、主题和托盘基础设施。MiniMax 在独立窗口加载本轮可信回环地址；登录弹窗继承该实例档案并返回原工作台。页面不拥有壳管理命令权限，外链、导航和回调按实际需要设置边界。

验证登录、页面渲染、点击与键盘输入、文件/目录选择、下载、剪贴板、同源 WebSocket、授权弹窗及关闭/重开后的登录与会话恢复。主题按当前窗口内容选择作用域，不用应用级主题改变另一窗口。实际 MiniMax 页面需要的浏览器能力若不受平台 WebView 支持，记录复现和替代方案，不声称已完整支持。

## 5. 已有工作如何处理

- **保留并重新接线**：隔离探针、版本/原生依赖检查、受控启动、Windows 独立 Job、正常停止、回环端口归属、独立 WebView 档案、授权弹窗和脱敏日志等可复用成果；以新调用链重新验证。
- **收敛**：当前未提交的独立 MiniMax 侧栏入口、`McodePanel.vue`、`McodeMemory.vue` 及其专用管理 store/命令属于实验实现，不作为最终产品结构；将可复用逻辑整合到现有概览、版本、插件、技能和记忆页面，再移除重复入口。不能把实验记忆页面当作记忆注入完成。
- **复用草稿并核验接线**：技能对账、MiniMax 记忆 hook 和受限桥已接入当前开发代码；仍须集中验证生产调用链，不能以代码接线或模拟结果宣称实际生效。
- **继续解决已知限制**：Windows 在候选组合下存在 SQLite 备份长路径限制；失去进程句柄后的旧记录当前缺少可用的自动恢复。建窗等待已改为 20 秒上限，顶层导航只允许本工作台回环页面，登录层与授权弹窗收尾已有实现——这三项都只有定向测试，仍待实机验收。保留失败与成功证据，不自动清理用户数据。

## 6. 实施顺序与分批提交

按用户要求先尽可能完成各功能代码，再集中进行功能测试和修正；已经完成的检查保留真实结果。验证后按独立功能块分别检查暂存范围并本地提交，不推送；不能把未完成或未验证的能力包装为已通过。

1. **目标选择与统一外壳**：盘点默认实例调用方，恢复内核切换器和实例解析；消除独立侧栏入口；补切换、迟到响应、未安装状态和 DSH 回归测试。

每项按 Windows、Intel macOS 分别记 `pass`、`fail`、`blocked` 或 `not_run`，记录候选提交、安装产物摘要、系统/WebView/Node/包版本、步骤与证据。自动测试和受控夹具不能代替真实 WebUI 或安装版验证。
