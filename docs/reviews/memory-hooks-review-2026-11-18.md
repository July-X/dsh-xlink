# 记忆与 Hook 复审修复记录

基线为 `64f8c3fa`。复审从面板、内置插件与 HTTP（超文本传输协议）入口读到任务表、收件箱和附件存储。以下条目在修改实现前登记，验收结果在本页回填。

| 编号 | 现象与根因 | 验收准则 |
| --- | --- | --- |
| M1 | 记忆提取的租约已经到期，只要还没人接管，旧任务仍可续期、结束、报错或提交候选。四个入口只比较令牌。 | 到期前接受当前令牌；到期时四个入口均拒绝。任务、租约与候选状态保持原样，随后仍可由新令牌接管。 |
| M2 | 提取调度先判断列表里有没有到期任务，再领取第一条待处理任务。靠前的任务若刚合并更新，会提前被领。仅剩已过期租约时也不会进入恢复分支。 | 有新旧任务交错时，只领已满静默期的任务；没有待处理项时，过期租约能被接管，达上限则记为失败；重复提交同一终止任务不重置尝试上限。 |
| M3 | MiniMax 记忆 Hook 按数据块将标准输入转成字符串。中文字符被分到两块时，传给检索的提示词或项目路径会出现替换字符。 | 用确定分片验证 Hook 的生产读取函数保持原文；另走真实 Hook 子进程核对中文检索参数。超出既有大小上限仍丢弃。 |
| M4 | 第二段提取任务的起点由壳计算，通常不为零。同一任务重排时，去重把这个派生起点也拿去比较，漏掉已在跑或已完成的任务。 | 同一会话、截止游标和提取器版本重复排队时，已运行任务返回 `already_running`，已完成任务返回 `already_settled`，不因起点不同多出任务。 |
| H1 | Hook 提交事件时先按事件 ID（标识）检查附件，归属校验在后。归属不符的请求可能看到附件状态，也可能触发事件状态写入。 | 提交前先查接入点归属。归属不符返回与不存在事件相同的结果，该事件及其附件状态保持原样；本接入点的正常提交、幂等提交和缺件提示照常工作。 |
| H2 | 停用 Hook 时即使配置落盘失败，面板也显示成功并返回成功。后端已在状态中给出失败原因。 | 落盘失败时面板仍显示当前监听状态，同时显示错误并返回失败；成功停用和保存已停用的设置仍显示成功。 |
| H3 | 删除事件尚未完成时，用户可以关闭详情再打开另一条。删除返回后，状态层和组件都会关掉当时打开的详情。 | 删除仍刷新收件箱；若用户已换到另一条，旧删除结果不关闭新详情。仍在查看被删事件时正常关窗。 |

## 验收结果

- M1：在到期前一毫秒和到期时分别检查租约。续期、完成、报错和候选提交都走同一有效期判断。回环路由测试确认过期提交没有留下候选。
- M2：混合队列只领取已过静默期的记录。磁盘上仅有过期任务时，生产领取入口能接管；达尝试上限的任务结为失败。
- M3：字节分片回归同时覆盖提示词与项目路径，真实子进程核对检索请求。已生成的内置资源与源码的 SHA-256（安全散列算法）摘要一致。
- M4：先完成第一段，再重复安排派生起点大于零的第二段，检查运行中和已结束两种状态；任务表只保留原有两条。
- H1：提交入口在读取附件前使用同一套按接入点查找事件的逻辑。原有的接入点隔离、正常提交、重复提交与附件缺失测试覆盖相关调用链。
- H2：原生测试注入停用写入失败，确认监听已停止、磁盘仍是上次设置、再次停用可保存。面板测试验证错误提示和未保存草稿保留。
- H3：界面测试在删除未返回时切换详情，确认已有的新详情保留；继续删除当前事件则正常关窗。
