## 3. 官网引用：文件、图片先查清，再补正确的降级说明

### 3.1 调查范围

沿“站点响应 → 壳内白名单裁剪 → 正文解析 → 固定快照 → 插件序列化 → 模型实际输入”逐层检查，分别记录 DeepSeek、MiniMax、ChatGPT 的结果。Windows 的自然响应与 macOS 的页内取数都要覆盖，防止一端在进入正文解析前就丢掉附件线索。

至少区分以下内容：

- 纯文本，以及用户在消息里粘贴的普通链接。
- 图片、仅含图片的消息、文字与图片混合消息。
- 文件名和附件标识、站点提取出的文件文本、原始文件字节。三者分别记录，不能拿文件名证明模型读到了文件。
- 生成文件、下载链接、需要登录的资源地址，以及工具输出中的引用。

优先使用合成数据与公开测试样本。真实账号只在已明确授权的隔离环境验证，不批量读取未选会话，不记录认证数据或私密附件正文。

### 3.2 首轮交付

形成逐站能力表，明确哪些信息进入快照和模型请求，哪些只剩元数据，哪些被省略。若夹具证实混合内容被静默跳过，补齐已有 `captureResult` 的省略/未支持说明，并让详情与模型输入使用同一事实；不得继续显示成完整引用。

本阶段先解决“是否正确引用、是否如实说明”。若用户需要模型实际识图或读取原文件，再根据站点的受约束取数能力、附件大小、模型能力与固定快照契约，提出最小扩展。不能把任意资源链接交给下载器，也不能默认将全部附件发送给模型。

### 3.3 验收

- 同一份混合消息经两平台裁剪后，保留的文字及已知省略事实一致。
- 模型请求逐项对照快照；未传图片字节或文件内容时，不得声称模型已看到。
- 仅附件消息、资源失效、鉴权失败与未知内容形态均有明确结果。
- 快照恢复、重复发送与失败拒绝发送等现有契约不回退。

主要入口：`src-tauri/src/official_chat/session_body.rs`、站点页内取数脚本、`plugins/official-chat/host/{protocol,commands}.js` 及客户端详情。需要扩展白名单或快照结构时，先更新同一份协议及兼容测试。

## 4. 预检物料复用：详细方案

### 4.1 现在为什么还会失败

当前过程是：

```text
预检：解析来源 → 下载 → 安装依赖/构建 → 临时实例启动验证 → 固定版本和摘要
应用：按固定来源再次安装 → 再核摘要/来源/版本 → 一致则成功，不一致则回滚
```

固定版本可以防止 `latest` 或分支直接换成另一份主包，但不能保证第二次解析到完全相同的依赖，构建脚本也可能受时间、环境和网络影响。当前摘要比对能拒绝差异，却要等第二次安装之后才能发现。因此用户仍可能遇到“预检已经通过，点应用却失败”。

复用要消除的是第二次取源和构建，保留现有校验、快照与回滚。兼容性预检仍以当前用户权限执行第三方代码；复用不把它变成系统安全沙盒，也不构成插件安全背书。

### 4.2 目标流程

```text
取源并校验 → 安装依赖/构建 → 形成可搬迁的物料
                           ↓
                   沙盒使用该物料启动验证
                           ↓
                   停止后核对内容未变化
                           ↓
                   发布计划与物料摘要
                           ↓ 用户点“应用变更”
校验计划/环境/物料 → 本地暂存并核摘要 → 发布到中央库 → 实例物化与接线
                                                ↓ 任一步失败
                                          恢复原状态并保留日志
```

物料须先满足可搬迁要求，再参与启动预检。不能在预检之后才改写依赖链接或补下载文件，否则装上的又不是验证过的那一份。

### 4.3 保存什么，放在哪里

- 保存插件运行文件、已经安装/构建的依赖闭包、可用锁文件与来源证据，以及带版本的安装计划。完整性校验继续沿用现有下载摘要要求。
- 计划包含目标内核及指纹、实例/profile（运行配置）、壳模式、平台/架构、Node 版本、物化模式和到期时间；摘要与物料清单相互绑定。
- 缓存路径经 `paths::*` 解析，随 `DSH_XLINK_HOME`，位于当前壳模式的专用目录。dev 与 release 不共用可写缓存；不写已安装内核树。
- 不能继续依赖沙盒临时路径或任意外部链接。优先复用现有复制与链接实现；pnpm 依赖必须完整，无法收束的外部链接要在预检前拒绝。确需引用目标内核只读宿主包的，必须登记并绑定其指纹。
- 计划与物料先写暂存目录，完成摘要后原子发布；半写文件不进入可应用集合。无须新增数据库或常驻服务。

### 4.4 应用时的边界

应用只接受服务端保存的计划标识，不信任客户端传入的物料路径。来源、目标实例、内核、运行环境、有效期或摘要任一不符，要求重新预检，不静默回退到联网重装。

正式应用不重新解析版本、不重新下载插件或依赖、不重复运行插件构建脚本。仍需进行的动作只有本地暂存、完整性检查、中央库发布和实例接线。若现有 profile 接线需要 pnpm，应限制为已备齐物料的本地离线操作；不能以接线为名恢复在线依赖解析。

复用既有变更前快照及安装回滚。除新安装外，还要覆盖更新已有插件：发布、物化或接线失败后，原插件文件、中央库记录、实例配置均可恢复。不能只恢复配置而丢掉旧插件实体。

关闭预检后的直接安装保持原路径；本轮不移除该能力，也不把用户选择直接安装伪装成已验证物料。

### 4.5 缓存生命周期

先沿用现有 30 分钟有效期与最多 16 份计划，不增加用户设置。重启后仅恢复版本、目标与摘要都有效的计划；旧格式或缺物料的报告明确要求重新预检。

应用期间持有物料使用权，清理不得删除正在应用的计划。成功、取消、失败和到期的处理分别测试；清理只处理专用目录中有本项目所有权标记的缓存，不遍历用户任意路径。写满、复制失败和中断必须保留原因及日志，不能发布半份计划。缓存字节上限在实现时依据代表性插件物料测量确定并记录，不先增加可调参数。

### 4.6 必须通过的行为测试

| 场景 | 预期 |
| --- | --- |
| 预检通过后断开取源服务再应用 | 成功；应用阶段外部取源、版本解析与插件构建调用次数均为零 |
| 上游 `latest`、分支或依赖发生变化 | 仍安装预检验证的物料；不受上游变化影响 |
| 物料被改动、缺文件、计划被篡改或过期 | 写目标实例前拒绝，提示重新预检 |
| 内核、实例、平台、Node 或物化模式变化 | 拒绝复用不匹配计划 |
| 应用中途失败，包括更新已有插件 | 原插件实体、中央库记录与接线恢复；错误给日志路径 |
| 重启、并发应用、取消与到期清理 | 有效计划可恢复，半成品不可用；在用物料不被清理 |
| pnpm 链接、Windows 文件占用与磁盘不足 | 行为明确，失败不破坏已有插件或用户目录 |

主要改动面：`plugins/install_plan.rs`、`plugins/precheck.rs`、`plugins/center.rs` 的取源/发布事务、`shell/paths.rs` 及预检报告测试。只有报告契约确需变化时才同步前端，不重做插件管理页面。

## 5. 退出登录：清认证，保留会话

默认退出清除当前壳的账户令牌、身份令牌、刷新令牌及账户身份残留；历史非活跃认证条目也不能继续作为备用登录。应用注册标识、宿主标识和加密文件密钥属于应用级材料，不能当作已登录状态；保留或回收须按现有注册与存储契约处理，不扩成账户管理功能。

会话日志、工作区、附件、官网引用快照及记忆均不在清理范围；不读取或清理本机 Codex 的认证。关闭插件与退出登录仍是两个动作，不将关闭插件改成自动退出。

实施顺序：

1. 取消正在进行的登录，阻止迟到的授权回调重新写入。
2. 与令牌刷新共用读改写串行边界，先可靠提交本地认证清理。
3. 再尝试远端吊销。网络失败或没有吊销端点时，说明“本地已退出、远端未确认”；本地文件写失败则不能报退出成功。
4. 向工作台与管理面板广播实际状态，避免本地已清理而界面仍显示登录。

验收覆盖断网退出、吊销失败、重复退出、凭据写失败、刷新与登录回调竞态。预置会话及附件摘要在退出前后必须不变；真实系统凭据库不进自动测试。不新增“删除数据”按钮、多账户列表或独立测试连接。

主要入口：`openai/flow.rs`、`refresh.rs`、`cmd.rs` 及现有账户状态消费者。退出前已发送的远端请求不能被本地清理撤回，不把这一点写成已撤销授权。

## 6. 通知：准确回到会话，锁屏隐藏敏感内容

### 6.1 点击通知定位

每条通知携带对应会话的受约束标识，并绑定所属壳模式与实例；不把正文或项目路径放进激活参数。Windows 保留单实例与跨进程交接，macOS 使用通知本身的激活回执，不能再靠“最近完成的那条”猜用户点了哪条。

收到点击后打开或聚焦现有工作台，再调用目标内核已验证的公开导航服务。页面未就绪时保留一次待处理目标，客户端就绪后消费；重复点击与乱序回包不得把用户送回旧目标。不通过伪造网址、操作会话列表 DOM（文档对象模型）或修改内核实现跳转。

预计需要壳侧导航队列与一个最小客户端接入点；优先复用现有插件资源、物化和公开扩展机制。该接入服务于系统通知，不增加要求用户启用另一个插件的步骤。支持窗口内的导航接口须逐版本验证；缺失就明确登记兼容缺口，不能只做“窗口弹出”便验收通过。

目标会话已删除、实例已变或内核未运行时给可见说明，不自动创建同名新会话，不启动另一个实例。锁屏期间如收到点击，导航等待用户解锁，不能因解锁本身打开未点击的会话。

### 6.2 锁屏隐私

发送时从系统读取锁屏状态；锁屏或状态不可确认时，仅发送固定的“任务已完成”提示，隐藏标题、提问、回复、项目名和路径。应用未读计数保留；工作台焦点状态不能代替系统锁屏状态。

解锁后仅后续新通知恢复正常，旧通知不补发敏感内容。还须检查锁屏前已投递的通知：只清理或脱敏属于本应用的敏感通知，避免它们留在锁屏通知中心，不动其他应用通知。系统权限拒绝、睡眠唤醒、状态查询失败和锁屏事件漏报均按隐私优先处理，不降级为显示全文。

本轮按固定默认行为实现，不新增隐私选项页。两平台使用现有原生能力及依赖，尽量不增加第三方包；具体系统接口经官方资料和本机行为核对后落定。

### 6.3 验收

- A、B 两个会话依次完成，分别点击对应通知，各自打开正确会话；不能总是打开最后完成的 B。
- 覆盖工作台已开/未开/正在加载、第二进程交接、重复点击、会话删除及 dev/release 并行。
- 锁屏期间的系统通知实际载荷与可见内容不含敏感字段；仅测试正文格式化函数不算通过。
- 覆盖锁屏前已投递通知、锁屏时刻竞态、未知状态、睡眠唤醒和解锁；解锁不补发旧正文。
- Intel macOS 与 Windows 安装产物分别验收；模拟回调、开发构建或一平台通过不替代另一平台。

主要入口：`notify/task.rs`、`notify/activate.rs`、工作台建窗链、必要的客户端接入、命令权限及对应判据。保留现有通知总开关、提示音和未读语义。

## 7. 开发顺序与交付

| 顺序 | 可独立检查的交付 | 开始后必须留下的证据 |
| --- | --- | --- |
| 1 | 官网附件能力表与静默省略复现 | 三站/两平台逐层对照，明确源码结论、夹具结果和未执行实测 |
| 2 | 退出清理 | 离线、写失败与并发回归；会话/附件摘要保持不变 |
| 3 | 预检物料复用 | 预检后禁网仍可应用；无重复构建；篡改拒绝与失败回滚 |
| 4 | 通知精确定位 | 公开导航接口兼容核对，A/B 通知与跨进程完整链路 |
| 5 | 锁屏隐私及双平台收口 | 系统锁屏前后实际通知证据，状态未知时隐私降级 |

每块单独提交源码、相关测试和文档，避免把未验收的大改动混成一笔。先完成可在隔离环境验证的部分；真实账号、锁屏和安装产物未执行就保留未执行，不能写成完成。
