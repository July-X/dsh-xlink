# 官网对话直接引用开发计划

依据：[功能方案](official-chat-bridge-research.md)。目标体验固定为：**工作台输入 `@` → 选择官网对话 → 继续输入并发送。**

本文指导 agent 分阶段实现，不代表功能已经实现。当前只完成方案与代码阅读；阶段状态均为待实施。实现者先读仓库根 `AGENTS.md`，修改 Rust 或面板时再读对应子目录约定。

## 1. 交付范围

首个可用版本完成一个站点的完整链路：按需查询官网目录、选中读取正文、自动固定快照、插入原生引用标签、正常发送并核对模型输入。站点先后由取数实测决定，不能因为资料里有端点就标为支持。

正常流程不得增加前置导入、复制、切窗或强制预览。官网窗口无需保持前台，未挂载站点的读取上下文按需建立；首次登录仍交给用户。读取失败留在原草稿附近处理，不把导入操作放回流程。

首版以结构化文本为交付范围，保留用户与助手的角色、当前有效分支、来源和时间。图片、附件、工具与思维内容不能伪装为已支持；遇到这些内容应给出明确范围与省略事实。完整多媒体支持另行排期。

固定约束：

- 自有 `@` source（候选来源）与 host（宿主侧）插件展开是主路线；不伪造内核会话文件，不通过模型主动召回未选中的官网历史。
- 目录只取必要元数据，正文只取选中对话；不启动后台全量同步，不为搜索提前下载所有正文。
- 官网正文进入独立的不受信任 user（用户角色）消息，不进入系统提示。用户发送前可以查看、移除引用。
- 不写已安装内核，不导出站点凭据，不恢复官网页面的全局 Tauri 桥，不绕过站点验证挑战。
- 不新增内核包级补丁，不为一个站点换框架、网络栈或复制整套内置插件机制。
- 只更新方案和代码不等于授权发布。按仓库约定本地提交，不自行推送、打标签或发版。

## 2. 先解决的可行性限制

2026-10-20 只读检查本机 `0.2.1-rc.2` 安装包发现：`dsh-client-ui-input-trigger/lib/client.js` 的 `settle()` 在 1459–1472 行直接调用 `src.onPick(...)`，接着同步执行 `execute(outcome, hit.span)`。`execute()` 在 1364–1379 行读取普通结果对象的 `claim`、`text` 或 `insert`，没有等待 Promise（异步结果）。

因此，**不能直接实现 `async onPick()` 并认为内核会等待正文读取**。上述行号只对应本次读取版本，实现前应重新核对目标安装包，记录版本和源码摘要；不得改写安装包。

第一个阶段必须证明：利用已存在的插件扩展完成异步读取、读取期间继续编辑、发送等待/拒绝以及读取成功后的原生引用插入。调查 `claim`、会话作用域事件与编辑器已有提交扩展，但不要把内部事件名存在当作可用接口已经验证。

若现有接口不能同时满足这些条件，记录具体缺口和最小上游接口需求，停止依赖该能力的产品实现。仍可继续独立的协议和取数验证。不得用手动导入、无正文的临时标签、直接操作 Lexical 或修改内核来掩盖失败。

## 4. 模块边界和现有接线

下表中的新增位置是建议落点，按真实职责逐步建立，不预先生成空模块。

| 位置 | 职责 | 约束 |
| --- | --- | --- |
| `plugins/official-chat/package.json` | 新内置插件的 host/client 声明 | 包名 `xlink-official-chat`；声明客户端时同时配置 `exports["./client"]` |
| `plugins/official-chat/client/client.js` | 原生候选、选择状态、codec、来源和引用详情 | 所有声明在 `window.__ModuleLoader__.load` 的 factory 闭包内；沿用当前单文件交付能力，不直接 require 未打包的同目录文件 |
| `plugins/official-chat/host/` | 解析引用、读取固定快照、投影模型上下文 | 按需拆分 `reference.js`、`bridge.js`；不照搬 memory 的系统提示注入 |
| `plugins/official-chat/test/` | 插件行为、提交失败与模型请求捕获 | 复用现有测试方式，覆盖客户端重复求值和卸载；不只做源码字符串断言 |
| `src-tauri/src/official_chat/`（新增） | 协议、读取协调、目录缓存、正文快照、host 路由 | 属于独立功能组；`lib.rs` 只登记组，组内声明子模块 |
| 上述目录中的 `webview` / `script_eval` 职责 | 读取上下文生命周期、跨平台异步结果 | 只在平台差异确实出现时分文件；不持锁等待页面回调，不阻塞事件循环 |
| 上述目录中的 `providers/` | 各站点的目录与正文适配 | 按站点隔离解析、认证与能力；首站实现不预建通用插件平台 |
| `src-tauri/src/harness/official_chat.rs`、`commands.rs` | 现有官网页签、窗口/profile 与命令入口 | 与新服务复用必要配置；`commands.rs` 不承载缓存和取数主体 |
| `src-tauri/src/plugins/builtin/bridge.rs` | 已有实例级回环监听与鉴权 | 只增加路由分发；正文读取落在官方对话模块，不再造一个监听服务 |
| `ui/src/official-chat/`、`ui/src/shell/bridge.js` | 壳侧设置、首次说明与必要状态 | 工作台候选仍由内核客户端插件呈现，不能在壳里重造一张导入页面 |

新增内置插件要一起核对：

1. `src-tauri/src/plugins/builtin/builtins.rs` 与 `scripts/prepare-builtin-plugins.mjs` 的登记、`entries` 和现有计数测试。
2. 插件 package 声明、实际 host 静态依赖与 `peers`；客户端包依赖和 `inject` 服务名分别核对，不能混用。
3. 新命令定义、`lib.rs` 注册、`permissions/app-commands.json` 和 `capabilities/harness-remote.json` 的最小授权；官网远程页面不获得这些权限。必要的设置命令单独授给本地管理面板。
4. `package.json` 的插件测试入口与现有持续集成调用。新目录未纳入测试命令会造成假绿。
5. `npm run prep:builtin` 生成的资源必须包含新插件；生成资源不提交，不无故改 `tauri.conf.json` 的整目录资源映射。

插件启用、兼容状态、更新与卸载沿用已有内置插件机制。不可用站点或不兼容内核只显示对应能力不可用，不能拖垮工作台。ChatGPT 来源继续复用 `subscription_codex::chatgpt_web_available()` 的显式许可判据；它不等同于 ChatGPT 网页已登录，也不允许复用 Codex 凭据请求网页。

## 5. P0：先做三个独立验证

### G1：真实工作台内的选择和发送控制

在临时 `DSH_XLINK_HOME` 下启动测试实例，使用固定候选和正文，不接真实官网、不使用付费模型。

- 安装最小的 client/host 插件，通过真实内置物化链加载，在实际工作台 `@` 菜单看见来源。
- 给正文读取增加可控延迟。选择后允许继续编辑；读取期间发送不能漏掉引用，取消后恢复正常发送。
- 验证成功后才插入就绪 chip，并保留输入位置和用户后续输入；不通过 DOM（文档对象模型）覆盖编辑器或隐藏待完成占位符来规避约束。
- 用服务缺失、codec 缺失、插件卸载验证用户可见诊断。注册回执由独立于失败插件的检查路径观察。
- 记录实际使用的扩展接口、会话和草稿标识来源、取消方式、内核版本及失败行为。仅证明 `registerSource` 可调用不算通过。

### G2：异步 JavaScript 结果和首站可读性

先用可控页面验证延迟成功、Promise 拒绝、超时、导航和页面销毁，返回的必须是完成后的结构化数据。Windows 与 macOS 的等待机制分别验证，不能仅因为原生回调异步就判定成立。

再逐站做最小只读探测：已登录账户的有限目录、指定一条测试对话、正确活跃分支和角色。记录实际需要的认证上下文与有效 origin（来源域），敏感信息不进入证据文件。不能从同源 cookie 推断 token/账户请求头已经满足。

优先调查已有 DeepSeek 页签与资料明确的 ChatGPT；先通过者成为首站，不把调研排序当承诺。MiniMax 单列待验。只读探测涉及真实账号时只访问用户明确指定的测试对话；登录由用户完成，不扫描全部真实历史或自动探测私密内容。

### G3：官网窗口未打开时仍可读取

复用既有 profile 配置，在需要时创建不抢焦点的读取上下文。分别验证“页签已挂载”“官网窗口关闭”“尚未登录”“账号切换”“重定向”及用户打开/关闭官网窗口时的所有权转移。

必须记录实际 profile 和真实导航来源，避免挂到了空白新账号。若增加隐藏读取 webview（网页视图），由协调器追踪创建者、在途请求和闲置回收；完成或失败后释放自有闲置资源，不销毁用户正在使用的页签。不得启动所有站点作长期预热。

P0 产出 `official-chat-feasibility.md`：G1/G2/G3 结果、环境与版本、测试命令、脱敏证据、发现的接口限制，以及是否可以继续。文档由实际执行结果填写，禁止先写“通过”。

## 6. P1：冻结协议与状态机

先建立同一组 Rust/JavaScript 协议夹具和版本号，覆盖以下对象，再写站点业务代码。字段名可按仓库习惯调整，语义必须一致。

| 对象 | 必需语义 |
| --- | --- |
| 来源能力 | 稳定 providerId、是否可用/已登录、支持分页/搜索/文本范围、能力限制；不使用易变页签下标作来源 id |
| 请求上下文 | requestId、目标 sessionId、draftId/草稿代次、请求代次、有限超时与取消；标识来源必须通过 G1 验证 |
| 目录页 | 账户范围、会话 id、标题、更新时间、真实深链、游标、覆盖范围与是否还有下一页；不含正文 |
| 捕获结果 | 账户范围、会话 id、有效分支、消息角色和文本、完整性、未支持内容、省略事实、捕获/来源更新时间 |
| 固定快照 | schemaVersion、不可变 snapshotId、规范化内容摘要与捕获结果；与官网会话 id 分开 |
| 错误 | 稳定错误码、可重试性、用户下一步、关联 requestId 与脱敏日志路径；不得把内部异常串当成功值 |

错误至少区分：未登录、账户已变、来源不支持、接口结构变化、部分内容、正文超限、超时、取消、快照失效、内核不兼容。目录没有结果与目录读取失败是不同状态。

读取选择的状态机：

```text
selected → reading → validating → snapshot_saved → ready
     reading/validating → failed 或 cancelled
     任意未完成状态 → stale（目标草稿/账户已变，废弃回包）
ready → serialized → expanded → persisted
```

只有 `ready` 可形成就绪 chip。失败、取消、陈旧回包均不得清空或覆盖草稿。菜单关闭只取消目录请求，因选择而关闭菜单不能取消已开始的正文读取。一次请求只允许一个终态；取消后的迟到结果不得创建可引用快照。

服务端从已绑定实例、壳模式和实际站点账户推导命名空间。客户端传入的会话标识用于一致性校验，不构成授权。桥不接受任意路径、任意脚本、任意 URL（统一资源定位符）或调用方指定的账户目录。

接口职责建议：客户端命令负责 `capabilities/catalog/capture/cancel/preview`，host 回环路由只按固定 id 读取快照与必要的模型可见投影。名称在实施时统一登记。复用现有桥的鉴权与轮换，不复制监听器；新增 GET 查询路由使用精确路径匹配与参数校验。若必须增加请求体协议，先补完整定长读取与大小上限，不能复用只读到请求头的 `body_prefix`。

此阶段同时确定首版常量：目录页大小和缓存期限、搜索去抖、读取超时、最大正文/响应字节、缓存总量/保留期、单消息引用数及总上下文预算。常量集中配置并有边界测试；数值是待测的工程参数，不伪称来自站点限制。

## 7. P2：固定数据跑通插件与模型输入

使用同一协议接测试目录和测试正文，完成真正的“选择到发送”闭环。新客户端只声明已经验证能拿到的服务，遵守双层依赖声明和 factory 生命周期。重新求值、关闭来源或卸载时注销监听、取消在途任务，不留下重复来源和定时器。

host 在 `agent/pre-step` 中先获取下游决定；保留 reject（拒绝）的语义。只展开已接受的直接用户消息引用，不遍历所有历史消息重新注入，不改变工具、助手、系统消息的权限层级。结果在内核正确的消息持久化路径提交，后续模型步骤与会话恢复复用已捕获内容。

引用快照的包装包含来源、固定版本、角色、捕获时间、不受信任声明及省略事实。使用安全编码，正文中的标签、Markdown 链接或角色声明不能逃逸包装。单条与总量预算都要覆盖，不能让自有来源加上原生 `@session` 后绕过总预算。不能静默裁掉最新用户问题或其他正常消息。

G4 验收使用可捕获请求的本地模型桩（可控模型服务），复用 `plugins/memory/test/probe/` 中适用的测试方法，避免复制整套探针框架。必须断言：

- 用户原文和选中正文进入正确会话，同一份快照的正文只追加一次（不因内核重放/工具循环被多次追加）；同一消息内同一正文被引用两次则各送一份（S-7），角色为 user，系统提示中没有该正文。
- 多步工具循环、重复发送请求、排队/转向、重试、压缩与恢复不重复追加，也不重新访问官网。
- 快照缺失、读取失败、codec/owner 失联时，桩模型收到的对应请求次数为零，并有可见错误出口。
- 引用可删除，删除后正常发送；延迟、取消、乱序和会话切换不会使其他草稿丢字或串引用。

只有截图或输入框里出现 chip 不算 G4 通过。现有 `e2e` 主要驱动主壳，必须先证明驱动实际操作的是工作台 webview；在主壳调用命令成功不代替内核编辑器测试。

## 8. P3：快照、回环桥与自动回收

目录缓存和正文快照分开。所有路径跟随后端路径解析，按壳模式、内核族、实例、站点账户隔离；不在代码中展开真实用户 home。原子写、校验读和状态错误复用现有共享层。

正文保存与索引提交采用可恢复的顺序：先完成完整文件写入并验证摘要，再公布索引；失败不发布半条记录。崩溃残留只清本功能未引用的临时对象，恢复不得越出缓存根。禁止依靠两个独立文件各自原子写就宣称事务完成。

快照 id 标识固定版本，重新选择生成新版本；去重不能抹掉账户、分支或捕获事实。codec 在重试时不得把官网 id 重新解析成“最新正文”。

草稿和在途请求持有明确引用关系，自动回收只处理未引用记录。恢复前应先重建草稿引用关系，不能先回收再恢复。被遗弃草稿的引用如何释放、进程崩溃后如何调和，要有可测试规则；不能仅用进程内计数保证重启安全。

存储保护先评估已有私有原子写与平台存储能力。Unix 私有权限与 Windows 当前用户保护分别验证，不把 `0600` 或已有凭据 vault（加密存储）自动等同于完整跨平台加密。落盘策略写进 P0/P1 决策记录，日志与诊断包不收正文。

host 回环路由只返回请求的固定快照，账户/实例越界、无效 id、格式版本不支持和摘要错误均拒绝。受信 host 插件本就拥有内核进程权限，不声称这条桥能够沙盒化恶意插件；令牌不得暴露给网页或日志。

缓存清理不影响已经写入目标会话的引用上下文；已发送记录由会话生命周期管理。若溢出内容另行保存，检索位置也必须随会话保持有效，不能仍指向随时可淘汰的临时缓存。

## 9. P4：接入首个真实站点

每个 provider 只实现以下职责：探测当前账户、列目录、读取指定会话、规范化活跃分支与角色、构造受约束的来源链接。异步执行、取消、超时和快照保存由协调层统一处理。

目录有有效缓存时立即返回，再按本次用户操作更新；同一范围在途去重。取消订阅者不能误取消仍被其他请求使用的任务；所有订阅者离开后才取消共享读取。部分站点失败不拖住正常文件和内核会话候选。

先实现有限目录与最近对话，再实现游标和站点原生搜索。不支持原生搜索时只搜索已加载元数据并标出范围，不把有限页称为完整历史；不通过抓取全部正文补搜索。正文请求次数应与明确选中的不同对话对应，候选 hover（悬停）和键盘移动不读取正文。

当前主分支不明确、角色无法识别、正文结构变化时按协议返回明确状态。内容稳定前不标成功；连续 401、403、429 或验证挑战应停止重试并保留用户可理解的原因，不生成风控绕过逻辑。

登录账户变化后使旧目录缓存与未完成请求失效。已选择的固定快照仍保持原来源归属，不挂到新账号名下；可见范围与删除行为按 P1 已确定规则执行。

P4 必须使用用户指定的少量测试对话，与官网当前有效分支逐条核对。证据只保存脱敏标题、条数、内容摘要、成功/失败和请求数；不要提交账号、cookie、token 或私密对话样本。

## 10. P5：完成桌面交互与诊断

候选组提供独立加载、错误、翻页和登录入口。来源名称、标题、时间与图标足以区分引用，不只靠颜色。加载不能阻塞输入；错误不是一闪而过的 toast（短暂提示），而是在原位置可重试、取消。

选择读取期间继续输入不丢字，不把候选查询的取消信号复用成已选引用的生命周期。点击 chip 可查看真正绑定的快照、捕获时间、支持范围和截断事实；更新引用是用户主动动作，不修改原版本。

发送前显示实际接收服务商/端点。模型切换和队列路由变化重新计算，不按模型名称猜服务商；来源或接收方变化不能沿用过期文字。正常流程没有导入确认或逐次跨站弹窗，用户仍以原生发送动作提交消息。

客户端引用详情通过已经验证的插件扩展或壳侧详情窗口实现；复用壳侧查看器时仅在用户点击详情后打开，不弹出强制预览。管理面板新增状态和缓存设置仍走 `ui/src/shell/bridge.js`，遵守现有设计系统，不为本功能另起样式体系。

诊断至少记录来源、请求阶段、requestId、耗时、返回条数/字节数、错误分类和取消原因，走 `shell_events` 形成可查日志。对话正文、认证数据、敏感 URL 查询参数不落日志。注册超时的检查要能在插件未进入 `apply` 时工作。

Windows 与 Intel macOS 分别验 profile 复用、真实 origin、窗口焦点、取消、关闭、重建和闲置资源回收。缺少某平台证据时保留待验状态；编译通过不能代替桌面行为验收。

## 12. 验证命令与提交节奏

日常只跑命中的面，不在每阶段整跑全量检查。以下新增路径是计划中的测试位置，文件创建并接入后再执行，不是现有命令已通过的记录。

全新 checkout 先按仓库约定安装依赖并运行 `npm run prep:builtin`，再执行 Rust 检查；插件源码或资源登记改变后同样先重新生成资源。不要在缺少构建资源时把编译失败归因于新业务代码，也不要提交生成目录。

| 改动 | 验证方式 |
| --- | --- |
| client/host 插件 | `node --test plugins/official-chat/test/*.test.mjs`；新增脚本同时登记到 `test:plugin` |
| Rust 协议、协调与缓存 | `cargo test --manifest-path src-tauri/Cargo.toml --locked official_chat`；测试命名包含该范围，确认实际执行数不为零 |
| Rust 接线/平台调用 | `cargo check --manifest-path src-tauri/Cargo.toml --locked`、格式检查；平台专属部分在对应平台编译与运行 |
| 资源登记与新鲜度 | `npm run prep:builtin`，随后 `npm run check:builtin`、`node --test scripts/dev-builtin.test.mjs` |
| 权限和生产接线守卫 | 受影响的定向测试；修改判据时跑 `npm run check:invariants`，并验证摘掉接线会使判据失败 |
| 管理面板 | 相关 `ui/test` 用例及 `npm run build:ui` |
| 跨模块共享逻辑 | `npm run check:duplicates`；确认复用没有改变原调用方语义 |
| 原生体验 | 新增实际工作台端到端用例；现有驱动不能覆盖时记录真实手测步骤与缺口 |
| 发布前 | 用户明确要求发布后，在最终提交状态运行一次 `npm run check`，执行两平台交付验收 |

所有按 `paths::*` 解析目录的 Rust 测试持有 `crate::tests::scoped_xlink_home` 或模块等效 guard（作用域守卫）直到用例结束。模型桩、站点夹具、WebView profile 和实例均使用独立临时目录，子进程继承相同隔离环境。不能通过测试函数自己 `set_var` 就宣称实现了并发环境隔离。

原生验证先检查已有监听进程和端口，不修改用户端口、不结束用户实例。测试创建的进程、页面和临时读取上下文由创建者记录并释放。用过 MCP（模型上下文协议）浏览器时及时关闭自建页面，不误关用户浏览器。递归清理仍遵守仓库的确认与路径校验要求。

每个可以独立评审的阶段及时提交。提交前检查工作区、定向 diff 和暂存区，只暂存本阶段实际修改的文件；不使用全量 add，不卷入其他会话的改动。更新证据和阶段状态，不推送。跨阶段公共协议变化由同一集成者先提交，消费方再跟进。

## 13. Agent 执行与交接要求

从第一个未完成阶段开始，先核对工作区和现有实现，避免重复创建已被其他任务实现的模块。实施者可以调整文件拆分和测试组织，但必须保持产品流程、权限边界与阶段验收。

每次交接记录：

- 当前阶段、已经实现的行为、尚未通过的硬条件；不要用完成百分比代替证据。
- 实际修改文件与本地提交 id，协议/缓存版本变化，以及影响的调用方。
- 已执行验证的命令、结果和脱敏证据位置；静态测试、模型桩、真实内核、真实站点和两平台桌面验证分别写清。
- 下一步最小可执行任务、阻塞原因和已验证的可行替代。禁止把前置导入或修改内核写成默认退路。

P0 的结果记录在 `official-chat-feasibility.md`，后续进度与验收记录在 `official-chat-progress.md`；由实施阶段创建，不预填通过结果。本文保持实施规则，进度记录保存每阶段事实，避免长期互相改写。

首站交付完成的判定是：目标内核能力已验证，真实官网窗口不在前台时仍能直接 `@` 选择，模型收到正确且固定的引用，失败能阻止错误外发，缓存与资源能恢复和回收，目标平台验收完成。网站适配数量、标签截图或测试总数都不能代替这条判定。
