# 官网对话的账户身份契约

状态：2026-10-23 用户已接受最小身份契约及旧快照兼容规则。代码和模拟账户回归已接入，三站真实账号操作仍待验收。

## 问题

当前服务端将实例目录摘要用作 `accountScope`，能区分实例，不能区分同一站点的登录账户。目录缓存、在途捕获和快照读取因此无法可靠识别 A→B。客户端传来的范围不能补上服务端身份事实。

## 建议

在现役回环桥增加受约束的账户身份读取能力。只使用站点自然响应中已实测的稳定、非凭据账户标识；壳侧裁剪并计算摘要，回包只包含站点短码、不可逆身份摘要和可确认/未知状态。原始账户标识、邮箱、令牌及完整用户响应不出壳、不落诊断日志。不得把令牌摘要、浏览器目录、会话标识或当前选站当作账户身份。

插件将实例、壳模式、站点与动态账户摘要组合成范围。目录缓存按该范围分键；开始捕获、提交快照和发送读取都核对身份。换账户时拒绝旧在途结果；旧快照保留原来源，不迁移、不删除。身份未知时按现有 `account_changed` 拒绝受保护动作，不增加错误码。

现有目录与正文白名单不扩大为任意用户数据通道。身份回包使用单独、严格的字段校验，并同步桥命令登记、权限检查和双端测试。旧快照缺少实际账户身份时拒绝重新发送，界面提示重新选择；原文件继续保留。

## 实施前提与验证

必须先分别取得 DeepSeek、MiniMax、ChatGPT 的账户字段出处、身份失效时机和换账户读数。未验证的站点不填写猜测的字段或端点。身份观察必须能区分当前状态与旧缓存；只有旧快照或上次成功记录时不能宣称身份已确认。

回归覆盖固定实例与站点下 A→B、未知身份、捕获中切换、读取前切换、B 新引用、跨站同名标识、客户端伪造、旧快照兼容和不泄漏原始身份。真实站点验收只使用指定测试对话，并遵守隔离档案规则。

## 待确认的决定

用户已接受最小身份回包，以及“旧快照缺少真实账户身份时保留文件、重新发送需重选”的兼容规则。后续修改不能退回只校验实例目录，也不能自动删除旧引用文件。

## 当前接线

现役桥新增 `POST /v1/official-chat/account-identity`，请求严格为 `{"command":"accountIdentity","site":"deepseek|minimax|chatgpt"}`。实际 `site` 必须是其中一个短码，不传入拼接字符串。成功信封只有 `ok`、`site`、`identity`；身份对象只有 `status` 和 `fingerprint`，未知身份摘要为空。错误仍使用 P1 已有码。

当前选择器集中在 `src-tauri/src/official_chat/account_contract.rs`：DeepSeek 自然 `users/current` 响应的 `data.biz_data.id`；MiniMax `GET /v1/api/user/info` 的 `data.userInfo.realUserID`；ChatGPT `/api/auth/session` 的 `user.id`。只选这些明确路径，不尝试令牌、设备标识或会话编号兜底。MiniMax 的[公开请求实现](https://cdn.hailuoai.com/mavis-chat/prod-web-sh-0.1.220/_next/static/chunks/80239-4e3df09a7b248aea.js)与[页面初始化实现](https://cdn.hailuoai.com/mavis-chat/prod-web-sh-0.1.220/_next/static/chunks/app/(pages)/%5B%5B...mavisPath%5D%5D/page-c0841d51de2c89df.js)分别包含该请求和 `realUserID` 的用户状态映射；这些源码出处不能替代登录环境的真实字段验证。

macOS 先在页面内按身份白名单裁剪响应，防止同包中的 token、邮箱等进入回程槽位；壳再对非凭据标识计算摘要。每次身份确认使用独立读取窗及原取数通路，不复用目录缓存。账户变化或无法确认时，在目录轮次互斥范围内清掉对应站点的壳侧目录缓存，插件目录缓存按动态范围分键。捕获前后和快照读取均重新确认；重复核对在同一轮内按站点复用身份请求。

当前实现会增加身份确认等待及建窗次数，尚未测量真实站点耗时。不得为了提速缓存“上次已确认账户”，也不得将超时或字段变化当作身份相同。
