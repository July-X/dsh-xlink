# 官网对话引用：当前实现与剩余任务

发布基线：`53bee298`（v0.5.9，2026-10-23）。下文另列该基线之后本轮工作区的开发结果，尚未提交或发布。本文件记录当前实现和验收边界；新增完成项须附本轮验证结果。历史进度日志、方案中的目标和源码注释都不能单独作为完成证明。

## 已交付

- DeepSeek、MiniMax、ChatGPT 共用站点规格与取数链；工作台从 `@站点/` 选择会话。顶层只列来源站，进入第二层才读取该站目录。
- Windows 通过 CDP（Chrome 开发者工具协议）观测站点自然请求；macOS 采用页内同源取数，MiniMax 使用临时旁听。凭据不回传插件。
- 目录按站点缓存、去抖，失败缓存 2 秒、成功缓存 60 秒；端点按完整路径识别。ChatGPT 首个 401 不再抢占同次导航中后续成功响应，等待上限不延长。
- 选中后由服务端分配引用标识、保存固定快照与正文文件；发送读取该版本。快照缺失、摘要不符或读取失败时拒绝引用序列化。
- 快照原子发布、正文文件校验修复、序号跨进程互斥、占用记录与受约束回收已接线。重复识别和预算提示已实现，不自动合并正文。
- v0.5.9 已发布。最终提交本地 `pnpm run check` 成功，Rust 测试 1184 通过、12 忽略；Windows 与 Intel macOS 发布构建及持续集成通过。[发布验证](https://github.com/July-X/dsh-xlink/actions/runs/39936600606)。这些是该提交的证据，不是后续改动的验证结果。

## 保留的边界

- 目录最多展示最近 6 条，再按已加载元数据匹配关键词；不是全历史搜索。游标与站点原生搜索属于后续能力，不能靠批量抓正文补齐。
- MiniMax 只取不带 `before` 的正文候选，正文分页取全未兑现；ChatGPT 活跃分支和完整性仍需实测。未得到完整性证据时只说“已取到”。
- P1 登记的内核扩展缺口继续保留；G1-7 已用本项目的精确请求路由规避，不能再写成当前通道整体不通，也不能声称内核缺陷已修。
- P4 的 G4-29 临时回程槽位、G4-30 临时替换函数可被检测等仍是已知限制。不得将依赖修改内核或等待上游发版作为关闭方案。
- 安装版真实操作与开发版通过分开记录；忽略和未执行项目都不算通过。

## 接手顺序

先读本文件，再读执行指南和当前协议。R1–R4 的本轮实现已经接线，不重新开发同一条链；先完成 R5 的真实站点与原生验收，并记录实际问题。身份识别失败时查 `official-chat` 日志中的站点和阶段，不改成实例范围放行。

用户要求的下一次手测：在官网发起一条新的 web chat（网页对话），回工作台重新进入该站目录，确认新会话出现且正文被 dsh 内核准确引用。此次不代用户向官网发送测试消息。
