# Hook 可信局域网与简易接入实施计划

本轮目标：一个局域网接收开关、多个命名来源、一个真实发送工具、一个自动更新的收件箱。只用于用户明确选择的可信内部网络，不增加公网穿透、云中转或自动执行内容。

## 设计契约

- 枚举真实 IPv4 网卡及掩码；明确绑定所选私网地址。无已确认地址时暂停，不回退全网卡监听。支持 192.168/16、10/8、172.16/12。
- 默认允许所选接口的实际子网，跨 VLAN 通过高级设置明确添加可信私网 CIDR；使用真实 TCP peer 地址，不信任转发头。网络变化不能静默扩大权限。后台定期检测接口地址/掩码/在线状态变化后暂停且需重新启用；完全同名同 IP 同掩码的物理网络切换无法识别，不将接口身份包装成信任证明。
- HTTP 是可信局域网默认路径，内容和凭据明文；不可信网络需要另行加密。应用不能防止管理员自行 NAT/代理，系统防火墙仍是部署边界。
- 保留来源独立凭据、限额、超时、幂等、附件完整性及原子提交、本地管理 IPC。只被动收件，不自动执行消息或抓取远程 URL。
- 普通接入只填名称和来源类型。提供可执行测试命令、精确运行状态、最近接收反馈。Jenkins 的 LAN 地址与文档一致，TLS/反代为高级选项。
- 发送工具接收真实文字、标准输入和文件，自动处理协议字段与多阶段上传；同一投递重试保持 ID、时间和正文不变。凭据通过环境变量或受保护的配置输入，不写日志。
- 现有事件/上传/commit/receipt 协议与凭据保持兼容。底层可靠性不因 UX 简化而删除。
- 收件箱可见时自动刷新且避免覆盖新筛选/旧请求；容量与条数保护及去重保留限制明确披露，不声称无限保存。

## 执行顺序

1. 文档固定设计与验收契约（本文件）。
2. P0：网卡发现、选择、来源范围校验和失联状态；回归测试。
3. P0：来源模板、启用与复制发送测试闭环、Jenkins 指引一致。
4. P1：真实发送工具、重试与文件流程测试；自动刷新与容量说明。
5. 独立审查，定向测试、格式/构建/静态门禁；中文草稿 PR，不合并或发布。

## 验收与限制

自动测试覆盖私网范围、CIDR/掩码、多接口、拒绝来源、缺少已选地址、旧配置迁移、真实内容上传、幂等重试、失败退出及前端迟到响应。
实机验收需 Windows/macOS 接收端与另一台 Windows/Ubuntu 发送端、真实 Jenkins、多网卡/VPN、跨 VLAN、断网/IP 变化与休眠恢复；未执行不得以单元测试代替。
