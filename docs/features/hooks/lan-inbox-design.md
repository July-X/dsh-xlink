# dsh-xlink 局域网 Hook 与素材收件箱设计

2026-11-17：当前产品方向为可信局域网收件箱；本轮实施契约见[简易接入计划](lan-simple-plan.md)。下文阶段日志是历史记录，网络范围以 §4 为准，容量/条数与墓碑上限以文末最新口径及部署指南为准。

版本：v0.1 · 日期：2026-11-16 · 状态：P0–P4 已实现（默认关闭、监听所有网卡；纯文本 + 图片/日志附件）；P5 实机验收未完成

> 本文定义目标设计，不代表全部能力已实现。P0–P4（默认关闭、监听所有网卡；纯文本与图片/日志附件入箱）已落地，其余阶段以本文范围和验收标准为依据；具体执行顺序与当前状态见[开发计划](development-plan.md)。

## 1. 核心结论

将 Hook 定位为 **高可扩展的局域网事件与素材入口**：接收外部系统发送的文本、结构化参数、图片和日志文件，可靠入箱、分类暂存，再由后续具体业务 UI 选择素材并交给模型处理。

不是 Jenkins 专用接口，不是模型执行接口，也不是把现有内核插件桥开放到局域网。

```text
外部工具 / Jenkins / 脚本
          │ 事件、参数、附件
          ▼
独立 Hook 接收器 → 来源适配器 → 统一事件 + 素材存储
                                      │
                                      ▼
                             收件箱 / 分类 / 预览
                                      │ 后续功能、显式选择
                                      ▼
                        日志分析 / 图片理解 / 其他处理 UI
                                      │
                                      ▼
                              DSH / MiniMax
```

### 1.1 已确定的产品决策

1. 支持局域网来源，不局限于本机。
2. 接收文本参数、图片和日志文件，协议保留新增类型的能力。
3. 先接收、分类、暂存，后续再做针对性的模型处理。
4. **脱敏由发送方保证。接收端不负责自动脱敏、不提供脱敏检测保证，也不设置自动脱敏审核队列。**
5. Jenkins 继续采用 Notification，作为来源适配器之一；不能据此假设它能上传任意附件。
6. 私有仓库与同步问题暂时搁置；本文不依赖仓库选址。

### 1.2 第一阶段不做

- 自动调用模型、自动发送钉钉、自动重跑构建。
- 完整工作流引擎、节点画布、任意脚本执行、远程操作内核。
- 自动下载事件里给出的 URL，或读取发送方声明的本地路径。
- ZIP 解压、HTML/SVG 执行预览、可执行文件处理。
- 多节点集群、分布式高可用、任意大文件及断点续传。
- 接收端自动脱敏或“已安全/无敏感信息”的检测标签。

## 2. 责任边界

| 参与方 | 责任 |
|---|---|
| 发送方 | 内容授权与脱敏、事件 ID 稳定性、文件完整性、重试与失败告警 |
| Hook 接收器 | 身份认证、访问控制、协议/类型/大小校验、可靠存储、回执、配额及生命周期 |
| 来源适配器 | 把第三方事件转换为通用事件，不运行模型、不决定业务操作 |
| 收件箱 UI | 展示分类、上传状态和预览，不把素材解释为执行指令 |
| 后续业务模块 | 选择素材、确定模型及处理范围、记录处理结果 |

“发送方保证脱敏”不等于输入可信。接收端仍必须防止路径穿越、恶意文件、资源耗尽和提示词注入；这些是结构与执行安全，不是内容脱敏。

接入点创建时显示一次简短约定：**请确保发送内容已完成必要脱敏，并具有发送权限。** 不要求用户逐条重复确认。通用客户端可携带 `sender_policy: "sanitized"` 作为声明，不将其展示为系统认证；第三方兼容适配器可使用接入点级责任约定，避免伪造逐条声明。

## 3. 产品对象与分类原则

### 3.1 四个对象

- **接入点 Endpoint**：一个发送来源的接收配置，含名称、适配器、权限、类型白名单、配额和凭据。
- **事件 Event**：一条业务消息，含来源、外部 ID、类型、标题、时间、文本和结构化参数。
- **素材 Attachment**：图片或文本日志等文件，附属于事件；用内部随机 ID 定位，不以文件名定位。
- **处理任务 Processing Job**：后续功能创建的独立对象，引用事件/素材；不改变原始事件内容。

### 3.2 分类不要混为一谈

采用两个维度：

1. **内容种类**：text、parameters、image、log。一个事件可同时包含多种内容，不强制选一个主类型。
2. **业务类型**：例如 `jenkins.build.finalized`、`screenshot.received`、`custom.message`，由来源和适配器决定。

文件 MIME 是技术格式，`log` 是用途。文本文件可标记为日志，但不能只凭 `.log` 后缀信任其内容。分类保留扩展注册点，首版未知类型明确拒绝，不自动启用新解析器。

## 4. 网络与部署设计

### 4.1 独立服务

- 独立端口、凭据和路由，不改变内核桥范围。默认关闭；首次启用必须确认真实网卡与私网 IPv4 地址，保留本机回环。
- 不允许全网卡或公网绑定；旧配置缺少网络选择、所选地址失联时暂停，不能回退 `0.0.0.0`。支持 192.168、10、172.16–31 企业内网。
- 按网卡实际掩码生成默认来源子网，通过 TCP peer 校验；跨 VLAN 在高级设置明确添加可信私网 CIDR。不信任转发头。
- UI 只提供实际可用地址，未运行显示原因，不复制占位符。端口占用明确失败，不偷偷换端口。网络变化不能静默切换网卡或扩大权限。
- 随桌面应用运行；退出、休眠或断网期间不可接收。发送端不得把连接成功或网络失败当作完整入箱。

### 4.2 推荐安全部署

默认是 **可信局域网直接 HTTP + 每来源凭据**。首次选择网络、启用服务、创建命名来源、从另一台机器发送测试并确认收到，构成接入闭环。无需域名、证书或反向代理。

HTTP 中令牌与素材均为明文。私网地址不是信任证明；不可信网络或敏感数据需另行加密。可选同机 HTTPS 代理到回环，但它不关闭原生 HTTP 路径，不能声称全链路强制加密。

防火墙由用户按网卡、端口及来源配置，不关闭防火墙、不自动开放端口。应用无法阻止管理员通过 NAT/代理另行暴露服务，不提供公网穿透能力；代理须自行限制来源，不信任 `X-Forwarded-*`。

## 5. 鉴权与权限

- 每个接入点独立随机令牌，发送方只获得该接入点的上传权限。
- 通用接口使用 `Authorization: Bearer <token>`，不把令牌放在查询参数。
- 接收端仅保存令牌的不可逆校验值，创建时显示一次，支持轮换和撤销；不写入日志。
- 暂停接入点立即拒绝新事件和新上传；已入箱内容仍可本地查看。删除接入点先停用凭据，数据清理单独进行。
- 接入点凭据不能读取其他事件、下载素材或修改服务设置。回执查询只能查询本接入点内容。
- 管理与预览通过桌面本地 IPC 或单独授权的管理接口，不能复用上传令牌。
- 默认不开放 CORS；若后续需要浏览器发送，单独设计精确来源白名单，不能简单 `*`。

## 6. 首版协议：JSON 事件 + 附件上传 + 提交

以下 URL、字段和默认值是待实现的 v1 协议设计，不代表现有 API。

### 6.1 为什么使用两阶段事件

有附件的消息需要区分“已收到元数据”和“全部素材已完整到达”。先创建草稿、上传预期附件，再提交成为可处理事件，避免 UI 或后续模型读到半个文件。

纯文本事件可以一次创建并提交。首版按整文件重传，不做分片续传；API 为后续上传会话扩展预留空间。

### 6.2 创建事件

`POST /hooks/v1/endpoints/{endpoint_id}/events`

```json
{
  "schema_version": "1.0",
  "external_id": "build:Project_Plague/Win64:128",
  "event_type": "build.materials",
  "occurred_at": "2026-11-15T02:00:00Z",
  "title": "Project_Plague Win64 #128",
  "text": "构建结果与已脱敏材料",
  "parameters": {"job": "Project_Plague/Win64", "build": 128, "result": "FAILURE"},
  "sender_policy": "sanitized",
  "attachments": [
    {"client_id": "console", "kind": "log", "filename": "console.log", "media_type": "text/plain", "size_bytes": 52000, "encoding": "utf-8"},
    {"client_id": "screen", "kind": "image", "filename": "failure.png", "media_type": "image/png", "size_bytes": 280000}
  ],
  "commit": false
}
```

响应 `201 Created`：

```json
{
  "event_id": "evt_generated_id",
  "state": "receiving",
  "attachments": [
    {"client_id": "console", "attachment_id": "att_log_id"},
    {"client_id": "screen", "attachment_id": "att_image_id"}
  ],
  "expires_at": "2026-11-16T02:00:00Z"
}
```

- `external_id` 在接入点内必填且稳定。幂等键为接入点 + external_id。
- 相同 ID、相同规范化元数据重试返回原事件及状态；同 ID 不同内容返回 `409`，不静默覆盖。
- 参数仅接受 JSON 数据，限制深度、键数和总大小。不解析表达式，不读取路径。
- 无附件时允许 `commit:true`，持久化完成后直接返回 `ready`。

### 6.3 上传附件

`PUT /hooks/v1/endpoints/{endpoint_id}/events/{event_id}/attachments/{attachment_id}`

请求体为原始文件字节，携带正确的 `Content-Type`。附件 ID 必须来自创建响应且属于本接入点与事件。

服务端流式写临时文件，实时计数、计算 SHA-256 并验证格式。发送方可声明 SHA-256；如提供则必须匹配。`Content-Length` 仅作提示，不能代替实际读取上限。拒绝请求体压缩以简化首版解压炸弹边界。

成功返回 `stored`、实际大小与 SHA-256。相同附件重复上传且字节一致返回原结果；不同内容返回 `409`。一旦事件 `ready`，禁止替换原附件。

### 6.4 提交与查询

- `POST .../events/{event_id}/commit`：所有预期附件均 `stored` 且校验通过时，将事件置为 `ready`。缺失附件返回 `409 attachments_incomplete`，不标记完成。
- `GET .../events/{event_id}/receipt`：返回上传/提交状态，不返回原文或文件字节。仅本接入点凭据可查询。
- 网络中断后客户端先查询回执，再决定重试创建、上传或提交。
- `ready` 的含义是**内容已完整入箱**，不是已分析、已审核或已发通知。

### 6.5 错误契约

| 状态 | 含义及客户端动作 |
|---|---|
| 400 | 协议字段错误，修正后重试 |
| 401/403 | 凭据无效、撤销、无权限或来源不允许，停止盲目重试 |
| 404 | 对象不存在或不属于该凭据，不暴露其他接入点信息 |
| 409 | ID 冲突、附件不齐或状态冲突，查询状态并修正 |
| 413 | 超过内容大小或配额，不能自动无限重传 |
| 415 | 不支持或类型不匹配 |
| 429 | 超速/并发限制，依据 Retry-After 并退避 |
| 503 | 服务/存储暂不可用，退避重试；不得返回伪成功 |

错误只包含机器可读码、简短原因和追踪 ID，不包含令牌、完整原文、内部路径。

## 7. 内容范围与建议起始限制

以下数值是首版可配置的保守起点，需通过 Windows/macOS 实测调整，不是现有性能保证。

| 项目 | 建议起点 |
|---|---|
| JSON 请求 | 256 KiB，嵌套深度不超过 8 |
| 单条正文 | 64 KiB；更长内容走附件 |
| 图片 | PNG/JPEG/WebP 静态图；单个 10 MiB；解码后最多 25 MP |
| 日志/文本附件 | 纯文本，单个 50 MiB |
| 每事件 | 最多 10 个附件、总附件 100 MiB |
| 每接入点 | 60 次事件创建/分钟，最多 2 个并发上传 |
| 全局 | 最多 4 个并发上传，默认 5 GiB 存储预算 |
| 未完成事件 | 默认 24 小时过期 |
| 已入箱内容 | 不按时间删除；全局 5 GiB 预算，超出时清理最早的历史事件 |

支持文本附件 UTF-8，兼容显式声明的 GB18030/GBK；原字节保留。解码失败显示“无法按指定编码预览”，允许本地改用其他编码查看，不静默丢弃字节。Markdown 按纯文本展示，首版不渲染内嵌 HTML。

图片验证文件签名和可解码性，同时限制像素、内存、尺寸与解码耗时，避免小文件导致巨大展开。SVG、HTML、PDF、压缩包及二进制文件首版拒绝；扩展时通过类型处理器和独立测试增加，不直接放开 `application/octet-stream`。

## 8. 存储与一致性

### 8.1 布局

- SQLite 保存接入点、事件、附件元数据、配额预留、回执、审计和清理任务。
- 文件保存在应用专用数据目录，临时文件与正式文件同文件系统，便于原子移动。
- 文件名由服务端随机 ID 生成；原始名称只是显示字段，清理控制字符并限制长度。
- 不把存储目录作为静态网站目录，不接受发送方提供路径，不跟随符号链接。
- 首版单实例、单数据库，不把 SQLite 文件放到 NAS 共享目录用于多实例写入。

### 8.2 关键写入顺序

1. 创建事件事务预留配额并登记预期附件；并发请求不能各自通过检查后共同突破配额。
2. 上传到临时文件，限制实际字节并完成哈希/格式校验。
3. 刷新文件，原子移动到正式对象路径，再在事务中登记附件 `stored`。
4. 提交事件前核验全部附件；数据库事务将事件切换为 `ready`。
5. 成功响应只能在对应持久化步骤完成后返回。

文件系统与数据库不是一个事务。进程可能在移动文件后、更新数据库前退出：启动恢复扫描处理孤立文件、丢失文件与未完成条目，不能假定两者永远一致。发现文件缺失时将事件标记 `unavailable` 并告警，不维持可处理状态。

### 8.3 状态分离

```text
事件接收：receiving → ready
            ├→ rejected
            ├→ expired（接收超时）
            ├→ evicted（容量满，清理最早的历史内容）
            └→ unavailable（恢复检查发现内容损坏/丢失）

附件：pending → uploading → stored
                   └→ failed

后续处理任务：queued → running → succeeded / failed / cancelled
```

后续任务状态不覆盖接收状态。一个事件可以被多个业务 UI 多次处理，任务引用不可变素材及内容哈希。失败后重试创建新的 attempt，不修改原始内容来伪装重试。

## 9. 生命周期与清理

- 显示总占用、接入点占用与剩余配额；容量是唯一的自动清理依据（2026-11-15 用户决定）。
- 已入箱内容不按时间删除。新事件需要空间时，按 received_at 从旧到新清理 `ready` / `unavailable` / 尚未清内容的 `expired` 事件：先清数据库内容与附件行，事务提交后删文件；事件转 `evicted`，墓碑最多保留 30 天（条数压力下可提前回收）；每次清理写一条汇总壳日志（事件数与附件数），文件删除失败按事件 ID 记录。创建前先把任何接入点上已超时的接收中事件标成 `expired`，避免废弃上传跨接入点卡住容量。
- 正在上传的 `receiving` 事件与正在预览的文件不参与容量清理；只有没有可清理的历史事件时才拒绝新事件（413），不删未完成的上传。
- 文件删除失败时附件行已清、文件成为孤儿，由维护线程按宽限期回收；失败写壳日志，持续可见。
- 手动永久删除明确显示范围和不可恢复后果；删除范围在确认前列出。
- 幂等回执/墓碑最多保留 30 天（条数压力下可提前回收），记录最小身份与哈希，不含原文。保留期内同 ID 重试返回 `expired` / `evicted` 状态，不重新创建；窗口之外不承诺去重。
- 应用备份必须同时覆盖数据库及文件，并验证恢复的一致性。

## 10. Jenkins Notification 兼容入口

独立兼容路由：`POST /hooks/v1/endpoints/{endpoint_id}/jenkins-notification`。

其职责仅为把回调规范化为一个**元数据事件**。回执代表入箱，不意味着已向 Jenkins 核验结果。记录 `reported_result`，后续业务取得实际构建状态时另存 `verified_result`。

配置方向仍为 JSON、HTTP、Finalized、日志行数 0。插件凭据配置与实际版本需验证；参考发布版源码，Secret text URL 可用于其认证方式，而 PUBLIC URL 可能出现在构建日志中。接入端对该适配器可提供独立 Basic 认证兼容，可信局域网可直接使用 HTTP（明文），非可信网络需加密通道；不得把 Basic 凭据给其他路由复用。

2026-11-15 实施：每个接入点另有一枚独立的通知密码（notification_token_hash，只存 SHA-256），与 Bearer 令牌互不通用；Basic 用户名固定为 jenkins，密码为这枚令牌。插件 1.17 的 Protocol.java 会把 URL 里的 user:password@ 转成 Basic 头，所以 Jenkins 侧把含密码的完整 URL 存进 Secret text 凭据即可；不需要也不应使用 Public URL。只接受 phase = FINALIZED，其它阶段返回 400 unsupported_phase。映射结果是一个 ready 元数据事件：job.url（含文件夹路径）优先作为 Job 身份，缺失时标记 identity_resolved=false；幂等键由身份、构建号与阶段产生，同一构建同一终态重试返回原事件；身份未解析且显示名相同的 Job 会共用幂等键，内容不同时保守返回 409，不伪造完整路径。parameters 只放 reported_result 等元数据，不写 verified_result；不保存插件日志、工件或负载中的 URL。正文/参数上限沿用通用协议（参数 ≤64 KiB），请求体沿用 256 KiB。反向代理部署必须把上游 Host 改写为 IP:<端口>（域名 Host 会被拒绝），见[局域网部署与发送指南](lan-deployment.md)。

JSON 契约以插件 1.17 的 [Format.java](https://github.com/jenkinsci/notification-plugin/blob/notification-1.17/src/main/java/com/tikal/hudson/plugins/notification/Format.java) 和 [JobState.java](https://github.com/jenkinsci/notification-plugin/blob/notification-1.17/src/main/java/com/tikal/hudson/plugins/notification/model/JobState.java) 为准：根对象直接包含 `name`、`display_name`、`url`、`build`，没有额外 `job` 包装。`@XStreamAlias("job")` 只属于 XML。接收端同时兼容旧示例的 `{"job": {...}}` 结构；回归测试的主路径使用官方根对象格式。

**Notification 不等于通用附件上传客户端。** 图片、完整日志等若要进入收件箱，应由发送方工具调用通用上传 API；也可在未来增加显式配置的日志获取模块，但不能让当前接收器按回调 URL 自动抓取内容。

Job 身份必须绑定已配置 Jenkins 实例和允许范围。短名称不足以区分文件夹同名 Job；若无法从受约束的元数据确定完整路径，则使用接入点绑定 Job 或标记身份未解析，不能猜测。幂等键由实例身份、完整 Job、构建编号与阶段产生。不能通过访问任意 payload URL 来补身份。

第一阶段不承诺漏事件补查或真实 Jenkins 状态查询；这些属于后续来源业务功能。发送失败和未收到事件的可见性由发送方/接入点状态支持，而不是声称具备可靠消息队列。

参考：[Notification 1.17 配置源码](https://github.com/jenkinsci/notification-plugin/blob/notification-1.17/src/main/resources/com/tikal/hudson/plugins/notification/HudsonNotificationProperty/config.jelly)、[发送日志与重试实现](https://github.com/jenkinsci/notification-plugin/blob/notification-1.17/src/main/java/com/tikal/hudson/plugins/notification/Phase.java#L316-L369)。这些是已有静态研究依据，不是用户 Jenkins 实机验收。

## 11. UI 信息架构

建议新增一级入口 **「Hook」**，首版包含「收件箱」「接入点」，存储配置放在该模块设置中，不提前展示未实现的工作流画布。

### 11.1 收件箱

- 顶部只放类型/来源/状态筛选、搜索和容量入口。
- 紧凑列表：标题、来源、类型图标、附件数量/大小、接收时间、接收状态。
- 详情：正文、参数、附件、安全预览、技术信息折叠区。
- 上传未完成显示“接收中（1/2）”；可用显示“已入箱”，不显示“已审核”或“安全”。
- 不显示无实现的“AI 分析”开关。后续功能上线后再增加“使用…处理”入口。

### 11.2 接入点

展示名称、适配器、启用状态、最后接收时间、错误次数和复制地址。创建向导：名称/来源 → 允许类型与配额 → 凭据 → 发送示例 → 测试入箱。

令牌只在创建/轮换时显示一次；普通列表不显示密码，不把完整含凭据 URL 放到截图或日志。

### 11.3 视觉与交互

- 浅色采用已认可的 Kami 式简洁布局，保持内容密度，不用大块空卡片装饰。
- 暗色单独定义背景、边框、正文、次级文字和状态色。
- 必要说明放 tooltip 或折叠帮助，不展示 agent 内部备注。
- 键盘可达、焦点清晰，错误状态同时有文字与图标，不能仅凭颜色。
- 图片缩略图受尺寸限制；原图预览通过授权本地读取，不暴露 LAN 下载地址。

## 12. 扩展接口

架构建议拆成以下责任单元，名称是概念而非强制现有文件路径：

- `HookTransport`：HTTP/TLS 边界、认证、限流和上传。
- `SourceAdapter`：原始来源 → 统一事件；必须声明协议版本和支持类型。
- `ContentTypeHandler`：允许类型校验、元数据提取、安全预览，不执行业务。
- `InboxRepository`：事件、附件、配额和状态转换。
- `BlobStore`：流式写入、哈希、原子归档、读取与清理。
- `ProcessingProvider`（后续）：从 UI 授权选择的素材创建任务并返回结果。

新来源不应要求修改存储核心；新内容类型需注册验证器与预览策略。插件不能直接获得任意文件系统访问或接收令牌。

模型处理授权独立于入箱授权。发送到 Hook 不代表同意发给外部模型。后续 UI 明确展示选定素材、内核、执行环境及外部服务，再进行处理；日志文本永远不是工具指令。

## 15. P0 实现参数（2026-11-15 冻结）

以下是把 §6–§8 落成实现的冻结值。改动这些值等于改协议或安全边界，必须同步本文对应章节并补负向测试。

### 15.1 路径、配置与权限

- 配置：`<DSH_XLINK_HOME>/shell/<release|dev>/hooks/config.json`；数据库：同目录 `inbox.db`（WAL，运行时另有 `-wal`/`-shm`）；附件文件：`hooks/blobs/<event_id>/<attachment_id>`，临时上传文件：`hooks/tmp/`。按壳模式分家，不随内核族或实例变化。数据库 `user_version` 当前为 3（v1：事件；v2：附件占位与上传状态；v3：Jenkins 通知的独立 Basic 凭据）。
- 配置形状：`{"schema_version":1,"enabled":false,"port":17890}`。默认端口 release 17890 / dev 17891，两个壳可同时启用。文件不存在按默认关闭；损坏或更高版本时服务不启动、保存拒绝覆写，原文件保留。
- Unix 上 `hooks/` 目录 0700、配置文件与数据库 0600；Windows 依赖目录继承权限。备份必须在服务停止后连同 WAL/SHM 一起复制。

### 15.2 令牌与鉴权

- 每个接入点独立 256-bit 随机令牌（64 位十六进制），服务端只存 SHA-256 十六进制；创建/轮换时返回一次明文，列表、日志、审计永不含明文。
- 只接受 `Authorization: Bearer <token>`，不放到查询参数；令牌轮换后旧令牌立即失效；软删除立即清空凭据。
- Jenkins 通知另有一枚独立密码（同样只存 SHA-256），只在该路由的 Basic 认证里接受；Bearer 令牌不能进通知路由，通知密码也不能当 Bearer 用。通知密码轮换或删除接入点时立即失效。
- 路径里的 `endpoint_id` 必须等于令牌所属接入点，否则 404；事件按接入点隔离，跨接入点读写一律 404，不泄露对象存在性。
- 绑定明确选择的私网接口地址及 `127.0.0.1`，无可用已选地址时暂停。`Host` 只接受 `localhost:<实际端口>` 或任意 IP 字面量（含本机内网 IP），域名仍拒绝以保留 DNS rebinding 防护；不信任任何 `X-Forwarded-*`；无 CORS 响应头。

### 15.3 协议规范化与幂等

- `schema_version` 固定 `"1.0"`；顶层未知字段拒绝（400），`parameters` 内部自由 JSON，但必须是对象。
- 指纹字段顺序固定：schema_version、external_id、event_type、occurred_at（epoch ms）、title、text、parameters、attachments。附件按 client_id 排序后逐项纳入 client_id/kind/filename/media_type/encoding/size_bytes；SHA-256 十六进制。P1 时代附件为空数组，指纹与升级前兼容。
- 省略与显式默认等价：title/text 缺省或 null → 空串，parameters 缺省或 null → `{}`，attachments 缺省 → `[]`。`commit` 与 `sender_policy` 不计入指纹；`sender_policy` 只作为声明入库，不是认证。
- 同接入点 + 同 external_id：指纹相同返回原事件当前状态（200），不同返回 409 `event_conflict`；并发由 `IMMEDIATE` 事务 + 唯一约束收敛为一条。

### 15.4 限额、超时与并发

| 项 | P1 值 |
| --- | --- |
| JSON 请求体 | 256 KiB |
| 正文 / 标题 / external_id / event_type | 64 KiB / 512 字节 / 200 字符（无控制字符）/ 64 字节（`[A-Za-z0-9._-]`） |
| parameters | 对象；序列化 ≤64 KiB、节点 ≤512、深度 ≤8 |
| 附件数量 / 单事件合计 | 每事件 ≤10 个 / 合计 ≤100 MiB |
| 单张图片 | ≤10 MiB，像素 ≤25 MP；仅 PNG/JPEG/静态 WebP |
| 单个日志 | ≤50 MiB；`text/plain`，encoding ∈ utf-8/gb18030/gbk（默认 utf-8） |
| 存储预算 / 磁盘余量 | 全局 5 GiB；上传前要求磁盘余量 ≥ max(512 MiB, 本次大小×2) |
| 上传并发 | 全局 4 个工作线程；每接入点最多 2 个并发上传 |
| 上传租约 / 超时 | 120s 可被接管；单次请求总时长 300s |
| 工作线程 / 队列 | 4 / 16；队列满返回 503，不无限派生线程 |
| socket 读 / 写超时 | 5s / 5s |
| 速控 | 每接入点 60 次创建/分钟，超限 429 + `Retry-After` |
| 未完成事件 | 24h 惰性过期（创建/提交/查询前处理） |
| 容量策略 | 全局 5 GiB；创建事务内按 received_at 从旧到新清理 `ready`/`unavailable`/未清内容的 `expired` 事件的内容与附件，保留 `evicted` 墓碑 30 天；没有可清理历史事件时才返回 413 |
| 请求审计 | 最近 2000 条错误（request_id / 对象 ID / 错误码 / 时间，不含正文与令牌） |

### 15.5 错误码

| HTTP | code | 场景 |
| --- | --- | --- |
| 400 | `invalid_request` / `unsupported_phase` | JSON/字段/时间/Host/深度/未知字段/分块传输错误；通知阶段不是 FINALIZED |
| 401 | `unauthorized` | 缺失、无效、已轮换或已删除的令牌 |
| 403 | `forbidden` | 接入点已暂停 |
| 404 | `not_found` | 路由不存在或路径归属不匹配 |
| 409 | `event_conflict` / `state_conflict` / `attachments_incomplete` / `attachment_busy` / `attachment_mismatch` | 内容冲突 / 状态不允许 / 附件未传完 / 同附件并发上传 / 已存附件重传内容不一致 |
| 413 | `too_large` | 请求体、正文、参数、附件或存储预算超限 |
| 415 | `unsupported_media_type` | Content-Type/编码不符、非空附件、不允许的内容种类 |
| 429 | `rate_limited` | 超速 |
| 503 | `service_unavailable` | 数据库忙/失败、连接队列满 |

### 15.6 生命周期

- 设置默认关闭；启用后优先绑定 `192.168.*` + 本机回环并随壳运行，应用退出时先停接收器。端口占用/无权限时 running=false 且保留 enabled=true（下次启动重试），状态里带明确错误，不偷偷换端口。
- 停止：置取消旗标、自连唤醒 accept、shutdown 活动连接、join 工作线程；不留下仍监听的端口。
- 数据库更高版本拒绝打开（不删数据降级）；配置与数据库损坏都在状态中暴露，不静默重建。
- 后台维护线程随应用启动（与监听开关解耦，每 10 分钟）：核对已存储附件文件、清空接收超时的事件内容与文件、把占用降回 5 GiB 预算（无新事件时也执行）、删除 30 天外的 `expired`/`evicted` 墓碑、回收超过 24h 的临时与孤儿文件；文件缺失的事件标记 `unavailable`，不维持可处理状态。容量清理发生在创建事务内，维持线程只负责文件与墓碑。

### 15.7 附件、清理与已知边界

- 创建事件时只登记附件元数据（`pending`），文件经 `PUT .../attachments/{attachment_id}` 上传；声明带附件的事件必须 `commit:false`，全部附件 `stored` 后 commit 才转 `ready`。
- 上传前取 120s 租约（`pending` 或过期 `uploading` 可接管）；已 `stored` 的附件只接受字节一致的重传（返回原结果），不同内容 409；事件 `ready` 后拒绝替换。
- 文件先写 `hooks/tmp` 临时文件、算 SHA-256 与声明大小核对、做内容校验，`fsync` 后 rename 到 `hooks/blobs/<event_id>/<attachment_id>`；路径只由内部生成 ID 组成，文件名只是显示字段。可选请求头 `X-Content-SHA256` 必须与实测一致。
- 校验深度：PNG 校验签名、块 CRC、IHDR 尺寸/颜色类型、非隔行、非 APNG，并流式解压 IDAT 核对行字节数；JPEG 校验 SOI/SOF 尺寸/SOS/EOI 与段边界；WebP 校验 RIFF/VP8/VP8L/VP8X 尺寸并拒绝动画。**不做完整像素解码**——这是为避免引入三套解码器与高内存分配而冻结的边界，P3 预览若需要像素仍按同一边界处理。
- 文本日志声明 `utf-8` 时流式校验；`gb18030/gbk` 原字节保留，预览时按 UTF-8 有损解码并明确标记无法解码的页，不静默替换。
- P3 预览只走本地 IPC `hooks_attachment_preview`：相对路径由数据库记录解析，拒绝符号链接和非普通文件，文件大小必须与记录一致；图片 ≤10 MiB 整块 base64 返回，日志每页 64 KiB 并回传 `prev_offset` / `next_offset` / `invalid_utf8`。不做缩略图、不做完整像素解码，也不生成 LAN 可下载地址。
- 清理：`receiving` 超过 24h → `expired` 并清空内容/附件；`ready` / `unavailable` 不按时间删除。新事件超过 5 GiB 预算时，在创建事务内按 received_at 从旧到新把历史事件转 `evicted`、清空标题/正文/参数/附件行，提交后删文件；保留事件身份 30 天作为墓碑供幂等重试，超窗口删行。手动永久删除走本地 IPC（P3 面板展示删除范围），删除失败的文件由孤儿扫描在下轮重试。
- 5 GiB 存储预算按附件声明大小在创建事务内预留（临时与正式文件同计）；只有接收中的事件占用且没有可清理历史事件时才返回 413。磁盘余量不足 503，不落半条事件。


## 近期审查修复约束（2026-11-16）

- **上传归属**：数据库升级到 schema v4，每个上传尝试独立持有租约标识。租约接管后，旧请求不得完成或撤销新请求；每次归档使用独立路径且不覆盖已有文件，失败只删除本次尝试的文件。归档采用同文件系统硬链接发布，数据目录所在磁盘必须支持硬链接（例如 NTFS / APFS）；不支持时明确失败而不是退回覆盖写入。
- **连接预算**：连接登记随请求生命周期释放，包括队列满和取消。数据库不可用时，503 响应后的排空最多 250ms / 256KiB，慢发送者不能无限占用 worker。
- **容量口径**：正文、参数、标题、发送方策略以 UTF-8 字节计费，每条事件另预留 1024 字节元数据，加上附件声明预留，共用 5 GiB 预算。该值是逻辑预算而非 SQLite/WAL 文件大小。纯文本同样参与按容量淘汰；新事件写入前检查磁盘余量，已有事件幂等重试不受新增写入预检影响。
- **事件数量**：最多 10,000 条。压力下优先回收空墓碑，再清理最早已入箱/不可用/过期历史，不清理仍活跃的接收中事件；全部为活跃接收时拒绝新增。墓碑回收后不再承诺对应 ID 去重，发送方必须使用稳定且不复用的事件 ID。
- **启动与列表**：启动只做必要的数据库/监听预检，全量附件核对与清理统一由后台单例执行，退出时协作停止（单次数据库查询和目录枚举仍不可中途取消）。列表只返回摘要，正文与参数按详情请求读取。
- **界面状态**：删除失败可见，末页删除自动回退；离开页面后迟到的创建/轮换凭据不回填。已执行的后端轮换不会因界面取消而撤销，必要时重新轮换获取新凭据。
