# dsh-xlink 局域网 Hook 与素材收件箱设计

版本：v0.1 · 日期：2026-11-15 · 状态：设计评审稿

> 本文定义目标设计，不代表全部能力已实现。本 PR 仅提交设计与开发计划，不改变应用行为、网络设置或仓库结构。后续实现以本文范围和验收标准为依据。具体执行顺序见[开发计划](development-plan.md)。

## 1. 核心结论

将 Hook 定位为 **高可扩展的局域网事件与素材入口**：接收外部系统发送的文本、结构化参数、图片和日志文件，可靠入箱、分类暂存，再由后续具体业务 UI 选择素材并交给模型处理。

不是 Jenkins 专用接口，不是模型执行接口，也不是把现有内核插件桥开放到局域网。

```text
外部工具 / Jenkins / 脚本
          │ 事件、参数、附件
          ▼
独立 Hook 接收器 → 来源适配器 → 统一事件 + 素材存储
                                      │
                                      ▼
                             收件箱 / 分类 / 预览
                                      │ 后续功能、显式选择
                                      ▼
                        日志分析 / 图片理解 / 其他处理 UI
                                      │
                                      ▼
                              DSH / MiniMax
```

### 1.1 已确定的产品决策

1. 支持局域网来源，不局限于本机。
2. 接收文本参数、图片和日志文件，协议保留新增类型的能力。
3. 先接收、分类、暂存，后续再做针对性的模型处理。
4. **脱敏由发送方保证。接收端不负责自动脱敏、不提供脱敏检测保证，也不设置自动脱敏审核队列。**
5. Jenkins 继续采用 Notification，作为来源适配器之一；不能据此假设它能上传任意附件。
6. 私有仓库与同步问题暂时搁置；本文不依赖仓库选址。

### 1.2 第一阶段不做

- 自动调用模型、自动发送钉钉、自动重跑构建。
- 完整工作流引擎、节点画布、任意脚本执行、远程操作内核。
- 自动下载事件里给出的 URL，或读取发送方声明的本地路径。
- ZIP 解压、HTML/SVG 执行预览、可执行文件处理。
- 多节点集群、分布式高可用、任意大文件及断点续传。
- 接收端自动脱敏或“已安全/无敏感信息”的检测标签。

## 2. 责任边界

| 参与方 | 责任 |
|---|---|
| 发送方 | 内容授权与脱敏、事件 ID 稳定性、文件完整性、重试与失败告警 |
| Hook 接收器 | 身份认证、访问控制、协议/类型/大小校验、可靠存储、回执、配额及生命周期 |
| 来源适配器 | 把第三方事件转换为通用事件，不运行模型、不决定业务操作 |
| 收件箱 UI | 展示分类、上传状态和预览，不把素材解释为执行指令 |
| 后续业务模块 | 选择素材、确定模型及处理范围、记录处理结果 |

“发送方保证脱敏”不等于输入可信。接收端仍必须防止路径穿越、恶意文件、资源耗尽和提示词注入；这些是结构与执行安全，不是内容脱敏。

接入点创建时显示一次简短约定：**请确保发送内容已完成必要脱敏，并具有发送权限。** 不要求用户逐条重复确认。通用客户端可携带 `sender_policy: "sanitized"` 作为声明，不将其展示为系统认证；第三方兼容适配器可使用接入点级责任约定，避免伪造逐条声明。

## 3. 产品对象与分类原则

### 3.1 四个对象

- **接入点 Endpoint**：一个发送来源的接收配置，含名称、适配器、权限、类型白名单、配额和凭据。
- **事件 Event**：一条业务消息，含来源、外部 ID、类型、标题、时间、文本和结构化参数。
- **素材 Attachment**：图片或文本日志等文件，附属于事件；用内部随机 ID 定位，不以文件名定位。
- **处理任务 Processing Job**：后续功能创建的独立对象，引用事件/素材；不改变原始事件内容。

### 3.2 分类不要混为一谈

采用两个维度：

1. **内容种类**：text、parameters、image、log。一个事件可同时包含多种内容，不强制选一个主类型。
2. **业务类型**：例如 `jenkins.build.finalized`、`screenshot.received`、`custom.message`，由来源和适配器决定。

文件 MIME 是技术格式，`log` 是用途。文本文件可标记为日志，但不能只凭 `.log` 后缀信任其内容。分类保留扩展注册点，首版未知类型明确拒绝，不自动启用新解析器。

## 4. 网络与部署设计

### 4.1 独立服务

- 独立端口、独立凭据和独立路由，不改变现有内核桥的监听范围。
- 默认关闭。首次启用选择“仅本机”或“局域网”；默认不绑定所有网卡。
- UI 显示实际绑定地址、端口、服务状态和可复制接收地址。
- 网卡地址变化或端口占用时显示明确错误，不能悄悄改成 `0.0.0.0` 或另一个端口。
- 首版随桌面应用运行；退出、休眠或断网期间不可接收。发送方不能把网络失败当作已接收。

### 4.2 推荐安全部署

第一版推荐 **同机 HTTPS 反向代理 → 回环 Hook 服务**：外部访问用户选择的 LAN 地址，代理终止 TLS，后端仍仅本机可达。该方案能提供局域网接入，不意味着产品原生证书管理已经实现。

若提供直接 LAN HTTP 模式，必须作为显式的“不加密测试模式”：说明令牌和素材可被网络窃听，默认不启用，不用于敏感生产数据。不能把 Basic/Bearer 认证描述成加密传输。原生 TLS 可作为独立后续任务。

防火墙规则由用户选择的网卡、端口及来源范围控制，不关闭系统防火墙，也不未经确认自动添加规则。代理来源头仅信任明确配置的代理；不得任意信任 `X-Forwarded-For`。

## 5. 鉴权与权限

- 每个接入点独立随机令牌，发送方只获得该接入点的上传权限。
- 通用接口使用 `Authorization: Bearer <token>`，不把令牌放在查询参数。
- 接收端仅保存令牌的不可逆校验值，创建时显示一次，支持轮换和撤销；不写入日志。
- 暂停接入点立即拒绝新事件和新上传；已入箱内容仍可本地查看。删除接入点先停用凭据，数据清理单独进行。
- 接入点凭据不能读取其他事件、下载素材或修改服务设置。回执查询只能查询本接入点内容。
- 管理与预览通过桌面本地 IPC 或单独授权的管理接口，不能复用上传令牌。
- 默认不开放 CORS；若后续需要浏览器发送，单独设计精确来源白名单，不能简单 `*`。

## 6. 首版协议：JSON 事件 + 附件上传 + 提交

以下 URL、字段和默认值是待实现的 v1 协议设计，不代表现有 API。

### 6.1 为什么使用两阶段事件

有附件的消息需要区分“已收到元数据”和“全部素材已完整到达”。先创建草稿、上传预期附件，再提交成为可处理事件，避免 UI 或后续模型读到半个文件。

纯文本事件可以一次创建并提交。首版按整文件重传，不做分片续传；API 为后续上传会话扩展预留空间。

### 6.2 创建事件

`POST /hooks/v1/endpoints/{endpoint_id}/events`

```json
{
  "schema_version": "1.0",
  "external_id": "build:Project_Plague/Win64:128",
  "event_type": "build.materials",
  "occurred_at": "2026-11-15T02:00:00Z",
  "title": "Project_Plague Win64 #128",
  "text": "构建结果与已脱敏材料",
  "parameters": {"job": "Project_Plague/Win64", "build": 128, "result": "FAILURE"},
  "sender_policy": "sanitized",
  "attachments": [
    {"client_id": "console", "kind": "log", "filename": "console.log", "media_type": "text/plain", "size_bytes": 52000, "encoding": "utf-8"},
    {"client_id": "screen", "kind": "image", "filename": "failure.png", "media_type": "image/png", "size_bytes": 280000}
  ],
  "commit": false
}
```

响应 `201 Created`：

```json
{
  "event_id": "evt_generated_id",
  "state": "receiving",
  "attachments": [
    {"client_id": "console", "attachment_id": "att_log_id"},
    {"client_id": "screen", "attachment_id": "att_image_id"}
  ],
  "expires_at": "2026-11-16T02:00:00Z"
}
```

- `external_id` 在接入点内必填且稳定。幂等键为接入点 + external_id。
- 相同 ID、相同规范化元数据重试返回原事件及状态；同 ID 不同内容返回 `409`，不静默覆盖。
- 参数仅接受 JSON 数据，限制深度、键数和总大小。不解析表达式，不读取路径。
- 无附件时允许 `commit:true`，持久化完成后直接返回 `ready`。

### 6.3 上传附件

`PUT /hooks/v1/endpoints/{endpoint_id}/events/{event_id}/attachments/{attachment_id}`

请求体为原始文件字节，携带正确的 `Content-Type`。附件 ID 必须来自创建响应且属于本接入点与事件。

服务端流式写临时文件，实时计数、计算 SHA-256 并验证格式。发送方可声明 SHA-256；如提供则必须匹配。`Content-Length` 仅作提示，不能代替实际读取上限。拒绝请求体压缩以简化首版解压炸弹边界。

成功返回 `stored`、实际大小与 SHA-256。相同附件重复上传且字节一致返回原结果；不同内容返回 `409`。一旦事件 `ready`，禁止替换原附件。

### 6.4 提交与查询

- `POST .../events/{event_id}/commit`：所有预期附件均 `stored` 且校验通过时，将事件置为 `ready`。缺失附件返回 `409 attachments_incomplete`，不标记完成。
- `GET .../events/{event_id}/receipt`：返回上传/提交状态，不返回原文或文件字节。仅本接入点凭据可查询。
- 网络中断后客户端先查询回执，再决定重试创建、上传或提交。
- `ready` 的含义是**内容已完整入箱**，不是已分析、已审核或已发通知。

### 6.5 错误契约

| 状态 | 含义及客户端动作 |
|---|---|
| 400 | 协议字段错误，修正后重试 |
| 401/403 | 凭据无效、撤销、无权限或来源不允许，停止盲目重试 |
| 404 | 对象不存在或不属于该凭据，不暴露其他接入点信息 |
| 409 | ID 冲突、附件不齐或状态冲突，查询状态并修正 |
| 413 | 超过内容大小或配额，不能自动无限重传 |
| 415 | 不支持或类型不匹配 |
| 429 | 超速/并发限制，依据 Retry-After 并退避 |
| 503 | 服务/存储暂不可用，退避重试；不得返回伪成功 |

错误只包含机器可读码、简短原因和追踪 ID，不包含令牌、完整原文、内部路径。

## 7. 内容范围与建议起始限制

以下数值是首版可配置的保守起点，需通过 Windows/macOS 实测调整，不是现有性能保证。

| 项目 | 建议起点 |
|---|---|
| JSON 请求 | 256 KiB，嵌套深度不超过 8 |
| 单条正文 | 64 KiB；更长内容走附件 |
| 图片 | PNG/JPEG/WebP 静态图；单个 10 MiB；解码后最多 25 MP |
| 日志/文本附件 | 纯文本，单个 50 MiB |
| 每事件 | 最多 10 个附件、总附件 100 MiB |
| 每接入点 | 60 次事件创建/分钟，最多 2 个并发上传 |
| 全局 | 最多 4 个并发上传，默认 5 GiB 存储预算 |
| 未完成事件 | 默认 24 小时过期 |
| 已入箱内容 | 默认 7 天保留，可调整/固定保留，但仍占配额 |

支持文本附件 UTF-8，兼容显式声明的 GB18030/GBK；原字节保留。解码失败显示“无法按指定编码预览”，允许本地改用其他编码查看，不静默丢弃字节。Markdown 按纯文本展示，首版不渲染内嵌 HTML。

图片验证文件签名和可解码性，同时限制像素、内存、尺寸与解码耗时，避免小文件导致巨大展开。SVG、HTML、PDF、压缩包及二进制文件首版拒绝；扩展时通过类型处理器和独立测试增加，不直接放开 `application/octet-stream`。

## 8. 存储与一致性

### 8.1 布局

- SQLite 保存接入点、事件、附件元数据、配额预留、回执、审计和清理任务。
- 文件保存在应用专用数据目录，临时文件与正式文件同文件系统，便于原子移动。
- 文件名由服务端随机 ID 生成；原始名称只是显示字段，清理控制字符并限制长度。
- 不把存储目录作为静态网站目录，不接受发送方提供路径，不跟随符号链接。
- 首版单实例、单数据库，不把 SQLite 文件放到 NAS 共享目录用于多实例写入。

### 8.2 关键写入顺序

1. 创建事件事务预留配额并登记预期附件；并发请求不能各自通过检查后共同突破配额。
2. 上传到临时文件，限制实际字节并完成哈希/格式校验。
3. 刷新文件，原子移动到正式对象路径，再在事务中登记附件 `stored`。
4. 提交事件前核验全部附件；数据库事务将事件切换为 `ready`。
5. 成功响应只能在对应持久化步骤完成后返回。

文件系统与数据库不是一个事务。进程可能在移动文件后、更新数据库前退出：启动恢复扫描处理孤立文件、丢失文件与未完成条目，不能假定两者永远一致。发现文件缺失时将事件标记 `unavailable` 并告警，不维持可处理状态。

### 8.3 状态分离

```text
事件接收：receiving → ready
            ├→ rejected
            ├→ expired
            └→ unavailable（恢复检查发现内容损坏/丢失）

附件：pending → uploading → stored
                   └→ failed

后续处理任务：queued → running → succeeded / failed / cancelled
```

后续任务状态不覆盖接收状态。一个事件可以被多个业务 UI 多次处理，任务引用不可变素材及内容哈希。失败后重试创建新的 attempt，不修改原始内容来伪装重试。

## 9. 生命周期与清理

- 显示总占用、接入点占用、剩余配额和预计到期时间。
- 到期清理基于创建时固化的保留规则；规则变更不静默提前删除已有记录。
- 清理前将对象标记 `deleting`，以可重试任务删除文件，完成后删除或压缩元数据；失败持续可见。
- 正在上传、预览读取或被处理任务租约引用的素材不直接清除。处理租约有超时和恢复规则，避免永久泄漏。
- 固定保留不等于无限容量；满额时拒绝新上传，不默认静默删除旧内容。
- 手动永久删除明确显示范围和不可恢复后果；保留政策首次启用时让用户明确选择。
- 幂等回执/墓碑建议保留 30 天（可配置），记录最小身份与哈希，不含原文。保留期内同 ID 重试返回已过期/已删除状态，不重新创建；窗口之外不承诺去重。
- 应用备份必须同时覆盖数据库及文件，并验证恢复的一致性。

## 10. Jenkins Notification 兼容入口

独立兼容路由：`POST /hooks/v1/endpoints/{endpoint_id}/jenkins-notification`。

其职责仅为把回调规范化为一个**元数据事件**。回执代表入箱，不意味着已向 Jenkins 核验结果。记录 `reported_result`，后续业务取得实际构建状态时另存 `verified_result`。

配置方向仍为 JSON、HTTP、Finalized、日志行数 0。插件凭据配置与实际版本需验证；参考发布版源码，Secret text URL 可用于其认证方式，而 PUBLIC URL 可能出现在构建日志中。接入端对该适配器可提供独立 Basic 认证兼容，必须走 HTTPS；不得把 Basic 凭据给其他路由复用。

**Notification 不等于通用附件上传客户端。** 图片、完整日志等若要进入收件箱，应由发送方工具调用通用上传 API；也可在未来增加显式配置的日志获取模块，但不能让当前接收器按回调 URL 自动抓取内容。

Job 身份必须绑定已配置 Jenkins 实例和允许范围。短名称不足以区分文件夹同名 Job；若无法从受约束的元数据确定完整路径，则使用接入点绑定 Job 或标记身份未解析，不能猜测。幂等键由实例身份、完整 Job、构建编号与阶段产生。不能通过访问任意 payload URL 来补身份。

第一阶段不承诺漏事件补查或真实 Jenkins 状态查询；这些属于后续来源业务功能。发送失败和未收到事件的可见性由发送方/接入点状态支持，而不是声称具备可靠消息队列。

参考：[Notification 1.17 配置源码](https://github.com/jenkinsci/notification-plugin/blob/notification-1.17/src/main/resources/com/tikal/hudson/plugins/notification/HudsonNotificationProperty/config.jelly)、[发送日志与重试实现](https://github.com/jenkinsci/notification-plugin/blob/notification-1.17/src/main/java/com/tikal/hudson/plugins/notification/Phase.java#L316-L369)。这些是已有静态研究依据，不是用户 Jenkins 实机验收。

## 11. UI 信息架构

建议新增一级入口 **「Hook」**，首版包含「收件箱」「接入点」，存储配置放在该模块设置中，不提前展示未实现的工作流画布。

### 11.1 收件箱

- 顶部只放类型/来源/状态筛选、搜索和容量入口。
- 紧凑列表：标题、来源、类型图标、附件数量/大小、接收时间、接收状态。
- 详情：正文、参数、附件、安全预览、技术信息折叠区。
- 上传未完成显示“接收中（1/2）”；可用显示“已入箱”，不显示“已审核”或“安全”。
- 不显示无实现的“AI 分析”开关。后续功能上线后再增加“使用…处理”入口。

### 11.2 接入点

展示名称、适配器、启用状态、最后接收时间、错误次数和复制地址。创建向导：名称/来源 → 允许类型与配额 → 凭据 → 发送示例 → 测试入箱。

令牌只在创建/轮换时显示一次；普通列表不显示密码，不把完整含凭据 URL 放到截图或日志。

### 11.3 视觉与交互

- 浅色采用已认可的 Kami 式简洁布局，保持内容密度，不用大块空卡片装饰。
- 暗色单独定义背景、边框、正文、次级文字和状态色。
- 必要说明放 tooltip 或折叠帮助，不展示 agent 内部备注。
- 键盘可达、焦点清晰，错误状态同时有文字与图标，不能仅凭颜色。
- 图片缩略图受尺寸限制；原图预览通过授权本地读取，不暴露 LAN 下载地址。

## 12. 扩展接口

架构建议拆成以下责任单元，名称是概念而非强制现有文件路径：

- `HookTransport`：HTTP/TLS 边界、认证、限流和上传。
- `SourceAdapter`：原始来源 → 统一事件；必须声明协议版本和支持类型。
- `ContentTypeHandler`：允许类型校验、元数据提取、安全预览，不执行业务。
- `InboxRepository`：事件、附件、配额和状态转换。
- `BlobStore`：流式写入、哈希、原子归档、读取与清理。
- `ProcessingProvider`（后续）：从 UI 授权选择的素材创建任务并返回结果。

新来源不应要求修改存储核心；新内容类型需注册验证器与预览策略。插件不能直接获得任意文件系统访问或接收令牌。

模型处理授权独立于入箱授权。发送到 Hook 不代表同意发给外部模型。后续 UI 明确展示选定素材、内核、执行环境及外部服务，再进行处理；日志文本永远不是工具指令。

## 13. 开发分期与交付门禁

| 阶段 | 交付 | 完成门禁 |
|---|---|---|
| P0 设计冻结 | 协议、对象、配额、状态机、网络部署契约 | 发送方脱敏责任明确；无自动模型行为 |
| P1 文本入箱 | 独立服务、认证、接入点、JSON、幂等、数据库、收件箱 | 重启不丢已确认事件；跨接入点不可访问 |
| P2 附件 | 图片/文本日志上传、校验、归档、提交、预览与清理 | 半上传不可处理；并发配额不超限；恢复一致性通过 |
| P3 LAN 与兼容验收 | HTTPS 代理部署指引、选定来源限制、Notification 适配与示例客户端 | 两台机器实测；凭据撤销、错误回执和重试可验证 |
| P4 后续业务（另立任务） | 图片/日志处理 UI、内核适配、业务回查或通知 | 不在 Hook 接收层混入模型和业务权限 |

P1/P2 可先本机联调，但不能以仅回环版本宣布完成局域网产品。PR 使用中文说明，逐项列明已验证和未验证平台，不直接合并主分支。

### 13.1 必须覆盖的测试

1. 纯文本、混合参数、图片、中文日志、多个附件及多类型事件。
2. 同 ID 同内容重试、同 ID 不同内容冲突、附件重复提交与并发提交。
3. 上传中断、超时、半文件、哈希错误、磁盘满、数据库错误、崩溃后恢复。
4. 类型伪装、路径穿越、符号链接、超大像素、嵌套 JSON、超限流式上传。
5. 令牌无效/撤销/轮换、端点暂停、跨端点对象访问、管理权限隔离。
6. 数据过期、固定保留、配额耗尽、清理失败重试、处理租约与删除竞态。
7. Windows/macOS 文件路径、编码、端口占用、网卡变化、睡眠及重新启动。
8. LAN HTTPS 发送、未信任证书时失败、代理地址伪造、不同来源限制。
9. UI 亮暗主题、键盘操作、长文件名、失败原因及接收状态。
10. Notification 元数据转换、文件夹同名 Job、重复/迟到事件；不能误显示已核验。
11. 全流程不自动调用模型、不发送钉钉、不自动下载外部 URL。
12. 发送方声明脱敏不产生系统“检测通过”标签；服务日志不记录令牌或内容正文。

## 14. 当前实现事实与待验证项

已有一版本地原型包含独立回环接收器、鉴权、SQLite 入箱、幂等和元数据 UI，并有核心及前端测试通过的报告；**该原型不接收附件、不满足本文 LAN 素材入口目标，且尚未提交、推送或创建 PR。** 完整桌面编译及原生平台验收未完成，不能将其测试结果当作本文新增能力的验收。

待实现验证：实际网络部署、图片/日志上传、配额与清理、文件/数据库一致性、原生平台预览，以及用户实际 Notification 版本行为。

最终验收标准：外部机器能将已脱敏文本、参数、图片和日志可靠发送到指定接入点；dsh-xlink 清晰展示完整入箱状态、分类和安全预览；重试不重复、异常不伪成功、暂存可控；后续业务可以复用这些不可变素材，而不与 Hook 接收机制耦合。
