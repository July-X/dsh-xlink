# 局域网 Hook 与素材收件箱：开发计划

日期：2026-11-15 · 状态：P0–P3 已实施（Windows 本机自动验证 + 真实 IPC 实跑；P3 亮暗截图已产出，macOS 实机待验收）；P4–P5 待实施

本文把[设计契约](lan-inbox-design.md)拆成可独立审查的开发任务。协议字段、限额和安全边界只在设计契约维护；本文维护依赖、执行次序、产出和验收。P0–P3 已实施（见 §4 实施记录）；P3 已在 Windows 本机完成自动验证与真实 IPC 实跑并产出亮暗截图，但 macOS 实机与键盘逐项回归未做，不记为已验收。此前暂停的本地原型没有进入仓库，也不把原型测试结果记为本计划验收。

## 1. 交付目标与不可越界项

完成定义：另一台局域网机器可向指定接入点发送文本参数、图片和日志；应用能可靠入箱、分类暂存与安全预览，能解释失败并控制容量。未来业务 UI 能引用不可变素材，不必改写接收器。

- **发送方保证脱敏和发送权限**。接收端不负责自动脱敏、敏感词扫描或脱敏审核，不生成“无敏感内容”认证。输入结构安全、凭据保护与资源限制仍是接收端责任。
- 首期没有模型调用、钉钉发送、自动构建重跑、URL 抓取、任意脚本执行和自由工作流画布。
- Jenkins Notification 只作为元数据来源适配，不能被当作图片/日志文件上传客户端。
- 不为完成本功能改已安装内核，不暴露现有内核桥，不创建私有 Studio 仓库。
- 仅回环接收器、模拟 IPC 或浏览器页面演示不能替代 Windows/macOS 的局域网验收。

## 3. 里程碑与依赖图

```text
P0 协议/安全决策冻结
  └─ P1 核心存储与文本接收
       ├─ P2 附件上传与恢复一致性
       │    └─ P3 收件箱、预览和生命周期 UI
       └─ P4 LAN 部署与 Notification 适配
                └─ P5 双平台端到端验收（依赖 P2/P3/P4）
                     └─ 后续业务 UI / 模型处理（另立任务，不在首期）
```

P3 可先以合成数据并行搭骨架，P4 可并行做部署验证；不能因此绕过 P2 的安全预览和数据一致性门禁。每个里程碑使用独立实现 PR；设计 PR 不开启监听服务、不增加网络权限。

| 阶段 | 依赖 | 可审查产出 | 合并/交付门禁 |
| --- | --- | --- | --- |
| P0 | 无 | 协议样本、状态转换表、威胁边界、网络方式决策 | 未决项有结论；不把建议限制当已测性能 |
| P1 | P0 | 默认关闭的服务、凭据、数据库、纯文本入箱及回执 | 已成功回执事件重启可读；端点隔离与幂等成立 |
| P2 | P1 | 附件上传、格式验证、配额、原子归档、恢复与清理 | 半上传永不 ready；故障注入和并发预算测试通过 |
| P3 | P1/P2 | 接入点、收件箱、详情预览、容量/保留配置 | 真实 IPC 联通；双主题、键盘、重复操作和异常状态通过 |
| P4 | P0/P1 | LAN 安全部署、通用发送示例、Notification 元数据适配 | 两机 TLS 发送与撤销通过；不自动改防火墙；适配器不越权抓 URL |
| P5 | P2/P3/P4 | 双平台实机证据、操作说明、发布前风险清单 | 所有必需测试有结果；无阻断项才称首期完成 |

## 4. 可执行任务清单

以下均为未验收任务，不以代码提交或测试函数存在代替完成。每项交付时附 commit、执行命令、环境和结果。

### P0：先冻结实现会依赖的决策

- [x] **H00 协议夹具**：根据设计 §6 准备纯文本、混合附件、冲突重试、错误回执 JSON；规定字段缺省、时间格式、未知字段策略及 canonical fingerprint。哈希不含服务器生成时间；显式区分“省略”和默认值，确保跨客户端重试语义一致。
- [x] **H01 状态与幂等边界**：固定事件/附件/清理状态转换；对 `ready` 重复 commit 返回已有结果；已过期/已删事件返回墓碑而不是重建；同一附件并发上传只能一个写者持有租约，其余回执明确。
- [x] **H02 网络交付方式**：首选同机 HTTPS 代理到回环服务，给出局域网地址、可信证书与来源限制的可复验方案。若提供原生 LAN HTTP，只作为显式不加密测试模式，禁止文案称其安全。原生 TLS 证书管理不临时塞进附件 PR。
- [x] **H03 核对数据边界**：确认存储根路径、dev/release 隔离、文件权限、令牌校验值保存、备份与迁移方案。配额对临时、正式文件与预留量都计数；明确磁盘剩余空间保护阈值。

验收：逐条用成功/异常序列推演，协议没有“元数据已接收 = 全部素材完成”的歧义；端点 ID 不是密码；发送方脱敏责任不变。

### P1：独立接收器与文本入箱

- [x] **H10 服务生命周期**：默认不启动；设置显式启用后绑定指定地址/端口，端口占用报错；启动失败不显示已运行；停止后不接收新请求，活跃写入进入有界结束/取消流程。生产启动和退出调用链必须接线并测试。
- [x] **H11 接入点与认证**：随机高熵凭据、不可逆校验、轮换/撤销/暂停；管理与上传权限分开；日志脱离原文和令牌。轮换中的旧凭据失效语义明确，正在上传的处理策略记录到协议。
- [x] **H12 数据库与迁移**：建版本化 schema、事务和唯一约束；迁移前备份，失败保留数据并停止服务；不能静默重建空库。纯文本提交持久化后才回成功；读写异常提供追踪 ID 与受控持久诊断日志。
- [x] **H13 JSON 与回执接口**：有界请求解析、字段/深度/大小校验、端点隔离、幂等冲突响应；跨端点 ID 探测不能泄露对象存在性；配额预留在事务中完成。

验收：以真实 HTTP 请求验证鉴权、重启、并发同 ID、撤销和数据库失败；不能仅调用纯函数证明服务可用。此时仍不宣称 LAN 素材功能完成。

> **2026-11-15 实施记录**：H00–H03、H10–H13、H20–H24 已完成。命令：`cd src-tauri && cargo test --locked --lib hooks`（51 项通过，含真实 TCP 请求、附件上传/幂等/冲突、伪造图片与非法 UTF-8 拒绝、提交前文件缺失→unavailable、并发同 ID、重启持久化、跨接入点隔离、端口冲突、损坏配置与 v1→v2 迁移）；`cargo check --locked`、`cargo fmt --all -- --check`、`cargo clippy --locked --all-targets -- -D warnings`、`node scripts/check-invariants.mjs`、`node scripts/check-code-duplicates.mjs` 均通过。实现参数与已知边界（图片只做结构性校验、不做完整像素解码）冻结在[设计契约 §15](lan-inbox-design.md#15-p0-实现参数2026-11-15-冻结)。本机为 Windows；macOS 只有 CI 同批自动测试，没有实机证据。P3 起未开始；保留期暂时固定 7 天，可配置与手动删除的面板范围展示属 P3。

### P2：附件、安全预览基础与存储恢复

- [x] **H20 上传会话**：仅接受创建响应里的附件 ID；预留大小，整文件流式上传并实时限额；超限中止、释放或回收预留；连接超时/断开清理可恢复。拒绝请求体压缩和任意外部 URL。
- [x] **H21 类型处理器**：按设计白名单实现 PNG/JPEG/静态 WebP 与文本日志；验证签名、实际格式、像素/内存/耗时。动画或不支持变种明确拒绝，不默认绕过限制。日志保留原字节，编码预览失败可见，不静默替换后声称完整。
- [x] **H22 Blob 归档**：随机对象名、路径边界校验、防符号链接/目录联接；临时与正式路径同文件系统；哈希校验、持久刷新、原子移动后登记 stored。不得依赖不安全的“先检查路径再任意打开”模式。
- [x] **H23 提交与恢复**：仅所有附件完整才 ready；注入各写入边界崩溃；恢复时核对孤立文件、DB 缺失和实际文件损坏；修复不可证明完整的内容时标记 unavailable，不能伪造 ready。
- [x] **H24 保留与清理**：上传/预览/后续处理租约保护、到期任务、删除失败可重试、固定保留仍占配额；保留政策改变不追溯缩短既有寿命。先确认用户选择的清理规则；手动永久删除显示不可恢复范围。

验收：实际峰值占用不越过预算，不能只统计正式文件；Windows 上文件打开/删除竞争与 macOS 上路径/权限问题各有测试；崩溃恢复后重复发送仍返回原事件或明确墓碑。

### P4：LAN 接入、发送示例及来源兼容

- [ ] **H40 部署指引**：HTTPS 代理只转发 Hook 上传路由，不暴露管理 IPC/对象目录；可信证书校验、选定地址/网卡、精确来源范围、代理头信任边界、停用与恢复。防火墙改动单独征得用户同意，不执行关闭防火墙指令。
- [ ] **H41 通用发送示例**：文本一次提交，附件创建→上传→commit→receipt；令牌从运行时输入读取；断线先查回执，429/503 退避，409 不盲重试。仅用合成图片/日志，不假装自动脱敏；支持 Windows PowerShell 与 macOS 命令行可复现调用。
- [ ] **H42 Notification 适配**：独立 Basic 兼容凭据与 HTTPS 路由；Finalized 元数据映射；完整 Job 身份约束、未解析状态和重复事件；reported_result 不能标为 verified_result。不替插件承诺可靠投递，不自动补查/下载日志。
- [ ] **H43 来源扩展验证**：用一个非 Jenkins 的合成来源投递文本+图片事件，证明无需改存储模型即可新增适配器；新类型必须注册校验与预览，不开放任意二进制或动态代码插件。

验收：真实两机发送文本、图片、日志，验证端点撤销、不可信证书、来源被拒、网卡变更和休眠恢复。Notification 实测记录实际 Jenkins/Java/插件版本；版本未知时只标“静态适配测试通过”，不标兼容验收完成。

## 6. 验证命令与环境纪律

按每个 PR 的实际改动选择检查，以下不是要求纯文档 PR 编译整个应用：

- 文档：检查 UTF-8、恰好一个末尾换行、相对链接、代码块与 JSON 样例；`git diff --check`；运行命中的 `check:invariants` / `check:duplicates`。
- UI：相关 `ui/test/` 测试、`npm run build:ui`；真实桥接/端到端用 `npm run e2e -- --spec e2e/specs/hooks.spec.mjs`（隔离 home + 独立单实例通道），不只测 mock。
- Rust：`cargo test --locked --lib <筛选>`、`cargo check --locked`、格式和 Clippy；独立 crate 必须加入实际门禁，不能只有本地可跑。release 条件编译检查按仓库规则保留。
- 不新增 Linux 发布平台或 Linux runner，不以临时云环境测试代替 Windows/macOS 验收。全量 `npm run check` 只在版本发布前按仓库规则执行。
- 测试数据只进临时 `DSH_XLINK_HOME`；壳实跑同时隔离 `TAURI_CONFIG` 的 appDirectoriesOverride 和 `DSH_XLINK_CHANNEL_SUFFIX`。不触碰用户内核、真实日志、系统登录项或个人挂载卷。
- 不把凭据写进 fixture、截图、PR、命令行示例常量或 CI 输出。测试输出不能包含素材正文；故障证据使用合成数据。

## 7. PR 拆分、回滚和完成报告

每个阶段只暂存自己的文件；此前本地原型仅作参考，不整包混入。提交前逐文件核对 diff。建议 PR 标题依次为「Hook 协议与测试夹具」「文本接入与持久化」「附件与恢复」「收件箱管理」「局域网与来源适配」「实机验收与操作指南」，可根据实际职责合理拆小，不能把依赖未实现的 UI 标为可用。

每个实现 PR 的中文说明必须列出：

1. 关联任务编号、设计章节、明确未包含的功能；
2. schema/协议/配置变化以及兼容性，是否需要备份；
3. 执行过的命令、结果、commit 与平台；未执行项及原因；
4. UI 变更的亮暗主题真实截图；网络变更的两机证据；
5. 停用与回滚步骤：优先关闭接收服务，保留数据库和文件；旧版不认识 schema 时拒绝打开，不能删除数据降级；
6. 尚未解决的阻断项。未经用户要求不合并、不打 tag、不部署。

完成状态采用「未开始 / 实施中 / 自动验证通过 / 实机待验收 / 已验收 / 阻塞」。文档审查通过不等于代码已验收；CI 通过不等于网络和原生 UI 通过。

## 8. 后续功能的接入条件

P5 之后才另立模型处理任务：通过本地授权的 ProcessingProvider 引用事件 ID、附件 ID 和哈希，使用读取租约，结果存为独立任务，不修改原始素材。日志分析、图片理解、Jenkins 最终状态回查/补查和钉钉通知各自有业务契约与权限，不能回填进 Hook 接收链路。

后续发送给模型的授权独立于素材入箱；发送方脱敏承诺不等于自动发送到任意外部模型。首期只保留接口边界，不增加空按钮或尚无实现的自动执行开关。
