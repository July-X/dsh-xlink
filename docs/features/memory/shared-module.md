# 通用记忆模块：安全切片

2026-11-08 本地开发，未发布。目标是 dsh-xlink 统一管理记忆，DSH / MiniMax 只作为来源标记。当前先实现普通记忆的双向检索注入，保留原实例编辑入口。

## 使用与授权

记忆页使用一份列表，标明 DSH / MiniMax 来源、实例与项目范围；记录仍保存在各自空间，查看后可在来源侧编辑。页顶的两个开关分别控制接收方是否使用记忆。「授权范围」中可单独启用双向普通记忆互通，首次启用需确认当前 DSH / MiniMax 实例及 profile；该许可涵盖两侧现有和后续保存的普通记忆，不需要逐条授权。历史逐条授权仍可查看和撤销；隐藏 MiniMax 体验入口时，历史来源与授权管理保留，MiniMax 记录只读。

开发验收前先运行 npm run prep:builtin，重新构建并重启壳，再重新打开 DSH 工作台；旧插件不会发送 module_context 标记，不能用旧进程验收新模块。

启用后重启 MiniMax 工作台，以安装/启动已支持的记忆桥。已有记忆桥的工作台在后续上下文请求生效。DSH 使用现有动态上下文插件的 module_context=1 自动注入请求，工具搜索和 pending=1 提取仍走本实例原 ID 路径；MiniMax 使用 UserPromptSubmit hook，不修改内核包。实际送入模型仍受现有插件的回合及字节预算限制，不保证每条记忆每回合均注入。

关闭模块只撤销这份双向许可，旧实例开关与逐条授权保持原意。要停止某个内核接收记忆，应关闭页顶对应的接收方开关；它不删除记录、不撤销已有授权。MiniMax 的旧实例开关不能阻止已授权的模块检索。已发送到会话的上下文不能收回。

## 数据与范围

- 原始记忆继续保存在各实例 memory/profile/memory.json，不改 schema，不复制或搬库，不修改 use_approved。
- 新许可单独存于本壳 memory-sharing/module.json，dev/release 隔离。旧逐条 grants.json 不变。没有新许可时继续走旧路径。
- 许可绑定默认 DSH 与配置的 MiniMax 实例和当前 profile；配对变化时不扩大到新实例，需要重新确认。未知版本/损坏授权拒绝注入，可明确关闭后修复；损坏来源库不被覆盖。
- 接受状态的通用偏好可双向检索；项目记忆必须匹配项目路径，源内核的局部 workspace_id 不用于另一个内核。停用、删除、未确认候选不会通过新模块注入。
- 共享响应使用带来源命名空间的 ID，防止两库相同 ID 混淆；不会提示模型用本实例 memory_read 读取跨来源 ID。
- 授权与记录写入、桥响应使用现有共享锁串行化。关闭之后开始的响应不能沿用旧快照；已发出的响应不撤回。

## 保留与未完成范围

本轮不合并磁盘库、不统一写入命令、不新增 MiniMax 自动提取。交接、经验不跨来源共享；既有本侧 use_approved 下的交接/经验保留原路径与预算。跨来源主动 memory_read、来源回写使用计数和完整跨来源效果账本尚未实现，不把带命名空间 ID 的统计当成完整指标。
