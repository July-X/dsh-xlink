# 记忆扩展：工作交接与经验

用户于 2026-10-23 确认以下五项决策。实施范围来自 [PowerContext 借鉴计划](powercontext-extraction-plan.md)，不安装 PowerContext，也不增加外部服务。

## 建议决策

1. 本轮启动计划中的 P0–P5。`memory.json` 的 schema 从 5 升至 6，只加入交接、经验及经验候选所需字段；保留旧库读取能力。新版写入后，旧版拒绝写入，避免丢字段。
2. 经验默认范围采用计划建议的 `general`（通用偏好），审核时可以指定项目范围；未批准的经验不得召回。项目隔离继续由后端强制执行，用户需要在审核时确认通用经验不含项目专有内容。
3. 交接与记忆共用 `xlink.memory` 上下文贡献，正文分段渲染；交接按项目读取，首次取得后仅因交接变化更新，不做关键词检索。交接单次上限 4 KiB，独立计算字节预算，库变化刷新仍受现有次数限制；换目录清空缓存且不重置额度。经验沿用既有记忆字节预算。
4. 归档交接保留在面板和导出中，不参与注入。同一项目最多一条活动交接，写入和替换在同一文件锁事务内完成。
5. 新增第四个模型工具 `memory_context`，读取交接与经验；`memory_propose` 增加经验候选类型。模型只能提经验候选，不能写入权威经验或创建交接。原计划“不新增第四个工具”的文字据此修正。

## 实施与验证

按 P0 数据兼容、P1 交接、P2 注入、P3 经验、P4 工具、P5 验收推进。复用现有文件锁、候选审核、项目权限、关键词匹配、导出与面板组件，不引入向量检索、第二套审核流或完整修订历史。

每个阶段补齐受影响调用方与测试，同步设计稿、计划和进度表。验证覆盖旧库往返、并发活动交接唯一性、未审核经验不可召回、跨项目与子智能体隔离、换目录及预算，真机证据使用独立临时数据根。日常仅跑相关检查，全量门禁遵守仓库的发布前执行规则。

## 兼容性与成本

降级后的旧版只能读取 schema 6 库，不能继续写。通用经验会跨项目召回，审核入口必须明确展示范围。交接独立预算会增加模型上下文体积，实测需要记录注入字节及次数。

现有记忆功能的夹具修复、提取器版本溯源与界面验收不依赖本记录，可先完成。
