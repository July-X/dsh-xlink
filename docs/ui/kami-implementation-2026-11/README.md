# Kami 风格管理面板实施方案

状态：**P1–P4 已实施，实机验收未完成**（2026-11-10）。设计合同仍是后续验收与回归的基准；实施记录与 not_run 清单见 [validation.md](validation.md)。

代码基线：`main@262889c1bf5ffd6c8a7f82d30788f27c12aff4b3`，2026-11-10 核对。后续实施先同步 main，重查受影响的组件、动作与后端契约；如果行为已变化，先更新本方案的事实表，不能按旧接口猜测。

目标：以 [tw93/kami](https://github.com/tw93/kami) 的暖纸、留白、细分隔和克制强调统一七个管理页面，保留局部玻璃质感；同一套布局完整适配浅色与深色。**页面功能以当前代码为准，概念图只指导视觉，不是新增功能清单。**

阅读顺序：本文 → [两主题精确 token](tokens.json) → [验收步骤](acceptance.md) → [概念图与纠错](references.md) → [实施验证](validation.md)。数值唯一来源是 `tokens.json`，本文说明用途。不得从图片取样覆盖 token。

## 1 必须落实的设计决定

1. 浅色的画布 `#f5f4ed`、纸面 `#faf9f5`、正文 `#141413` 保留。主要动作使用墨蓝，避免大面积蓝底、荧光蓝、装饰渐变和纹理背景。
2. 深色沿用仓库已选的「夜航日志」：深墨绿画布、暖纸文字、黄铜操作色。**本轮没有新的暗色效果图，也没有重新选暗色调色板**；采用现有体系是兼容性决定，不得声称为用户新确认的暗色图。新布局、圆角、交互、玻璃层全部两主题同构。
3. 主内容是开放的账页分区：透明底、细线、留白，不是每块都套卡片。局部浮层允许半透明与模糊，正文区不能整页毛玻璃。
4. 内置与自装插件在**同一张列表**，只给内置项加「内置」徽标，不再另建「自装插件」分区或空框。每一行逐内核展示真实接入状态，可操作能力才给可用复选框，不支持必须写明。
5. 保留每个插件具体用途的 tooltip。删掉写给开发 agent 的常驻操作说明和重复介绍；不能借此隐藏错误、权限范围、安全代价或未支持能力。
6. 记忆模块启用行的 `DSH` 改为 **DeepSeek**。内部 id `dsh`、IPC 字段、存储命名不改。其他来源标签按真实来源语义保留，不做全仓字符串替换。
7. MiniMax 端口组保持粉色品牌词、粉色描边和「实验内核」标识，暗色使用单独粉色 token。粉色不挪作通用选中态。
8. 中文标题保留衬线，中文正文不换手写体；英文 DeepSeek / MiniMax 与侧栏英文品牌词保留现有手写体。侧栏品牌继续鲸眼红，不按某张概念图改成蓝色或黑色。
9. 保留所有已有功能和安全判断。不得为了复刻图中留白删除诊断、重试、许可、来源、未完成/失败状态。
10. 不改产品名、窗口尺寸、默认主题、导航顺序、内核安装与数据隔离边界，不升级依赖，不实现概念图虚构的数据源。

## 2 交付范围与旧约束的处理

### 2.1 本方案与实施 PR 的边界

本 PR 的文件都在 `docs/`。UI 实施应另开 PR。实施 PR 可以调整展示结构、语义 token、公共组件样式和必要无障碍语义，但必须复用原 store 动作与后端判断。

允许的视觉变化：控件圆角由旧 2px 改为 6px；行 hover/selected 为 6px；独立浮层 8px；主分区仍无外框无圆角。主内容列缝由 34px 收到 24px；统一页头与留白；插件列表合并；套餐用量改为横向行；记忆页收纳辅助说明。不得把外观调整变成新产品功能开发。

`ui/AGENTS.md` 中旧「2px 方角」「34px 列缝」「内置 → 安装 → 自装」布局条目目前仍描述已实现版本。**只有开始实施对应变更的 PR，才同步改这些条目与相关静态测试**，并链接本方案；本设计 PR 不提前改仓库现行规则。根 AGENTS、权限/数据边界、只读安装目录等硬约束始终有效。

### 2.2 优先级

- 安全与真实能力约束优先于视觉参考。
- 本方案的明确目标优先于七张图中互相矛盾的文案、状态、布局细节。
- 未被本方案明确替换的既有行为与仓库约束继续保留。
- 无法从源码确认的能力列为阻塞项，不画成可用。不能用 mock 结果宣称真实功能已经通过。

### 2.3 明确不实现

- 技能内置目录、搜索、精选榜、标签筛选及图里的推荐项。
- 新的「近期活动」跨模块事件流、用量事件和系统事件分类。
- 记忆跨来源统一导出/清空、MiniMax 自动会话提取、完整记忆操作历史。
- 任意 DSH 插件直接装入 MiniMax；把不支持改成一个可点开关。
- 原生可缩放窗口、移动端产品、全局窗口透明、上游内核修改。

## 3 总体骨架与精确尺寸

所有尺寸为 CSS px。概念图约为 1480×1060，不是生产窗口尺寸，不能原样按图片像素写 CSS。

| 部位 | 目标 |
| --- | --- |
| 主窗口 | 1040×748；继续不可缩放；平台标题按钮保持现有实现 |
| 标题栏 | 38 高；窗口顶部既有 2px dev/release 标识线保留 |
| 侧栏 | 展开 157；收起 64；不因页面、主题改变 |
| 主内容 | 横向 padding 24；顶 20；底 24；基准内容宽 835 |
| 页头 | min-height 48；左图标、h1、ⓘ，右侧仅真实页面动作；下方 1px 分隔 |
| 通用区间 | 页头后 16；分区上下 padding 14；独立块 gap 16；双列缝 24 |
| 双列 | 一般等宽；概览 1.25fr / 0.75fr；记忆 1.2fr / 1fr |
| 侧栏导航 | 行高 34，左右 padding 10，图标 17，图标与文案 gap 10，圆角 6 |
| 标题/列表图标 | 页头 22；分区图标槽 22；列表图标 16；状态点 6 |
| 表格/列表 | 表头 32；普通行 min-height 48，双行可增长；不能固定高度裁字 |
| 控件 | 高 30、左右 padding 12、gap 6、圆角 6；输入框字号 14 |
| icon-only | 可见 26×26，命中区 32×32，相邻命中区不得互相截断 |
| tooltip/浮层 | padding 10 12；圆角 8；最大宽 min(420px, 100vw - 32px) |
| 线 | 账页线 1px `--border`；输入控件边界用 `--control-border`；不满屏重框 |

主内容禁止固定像素宽的两列相加超过容器。对子项设置 `min-width: 0`；数字/短状态不换行，说明与长路径按词或任意长串换行。可截断项目名、路径预览，但必须有可聚焦的完整文本入口；版本号与关键按钮文案不能被省略。

### 3.1 页面公共结构

- 导航顺序不变：工作台（概览、用量分析）、资源（内核版本、插件、技能、记忆）、系统（设置）。导航图标与页头共用 `shell/pageIcons.js`。
- h1 为 31px / 600 / 衬线 / 1.2；图标离标题 10；ⓘ 离标题 8。默认不常驻一整句 page-desc，解释放标题旁 tooltip。
- 分区 h2 为 15px / 600 / 衬线 / 1.4；数据行 14px / 1.5；次要列 13px；徽标 12px；只允许图表轴等使用 10/11px，不把中文操作压小。
- 概览主版本号、KPI 20px / 600；余额/强调数值 18px。不能把图中放大的文字机械复制成 28px 数据读数。
- 数字 `font-variant-numeric: tabular-nums`；路径/版本读 `--font-mono`，不用不同平台字体偏移来硬凑对齐。
- 列表 hover 在分隔线内左右各留 6px，底板不贴边；只画一层 `--overlay-faint`。selected 使用 `--accent-fill`，hover 不覆盖 selected。
- 主内容行与卡片不加阴影。现有页头缎带、彩色径向光不保留在新七页主面板里；不另加噪点、装饰线条。

### 3.2 响应与缩放

生产窗口仍是 1040×748。以下是对收起侧栏、辅助窗口、浏览器测试与系统缩放的防溢出规则，不是授权新增移动端界面：

1. 主内容可用宽度 ≥720：按各页指定列数；<720：概览、设置、记忆变一列，保持 DOM 阅读顺序。使用主内容容器查询（容器不支持时给等价媒体查询回退），不能仅凭整窗 1040 判断能放下。
2. viewport <900：侧栏视觉收成 64px，保留所有图标 tooltip 和当前页可访问名；不得覆盖用户持久化的手动收起偏好。恢复宽度后按用户偏好展开。
3. 列表可用宽：插件≤767、技能<720时行变两行，第一行名称+状态+更多操作，第二行 DeepSeek / MiniMax 控件；不隐藏目标列。表格若必须横滚，只允许表格容器，不允许整个 app 横滚。
4. viewport <600：main padding 16；页头动作换第二行；安装输入占整行、按钮右对齐下一行。验收覆盖 520×748，无需声称这是支持的原生窗口规格。
5. 大部分页面只由 main 纵向滚动，不能 card 内再套滚动。记忆宽版是例外，见 §8.6；窄版/200% 文字缩放时退回整页滚动，避免嵌套裁切。
6. 保留字号，允许多行与纵滚。不能为首屏无滚动把文字缩小、隐藏错误或 `overflow: hidden` 掉动作。

## 4 两主题颜色合同

完整字面量在 [tokens.json](tokens.json) 的 `themes.light` / `themes.dark`，两组键必须完全一致。现有语义 token 继续沿用；新增 token 只为以前混在一起的控件边界、主按钮前景、可读品牌词、玻璃层和 tooltip。

| chrome | #efece3 | #0d1513 |

| 分隔线 / 可操作边界 | #d4cfc0 / #8a857a | #2a3932 / #71877a |
| 成功 / 警告 / 危险 | #256b4d / #7d5417 / #a6403a | #8fbfae / #d8a84e / #c96f5f |

品牌原色仍用于 logo/品牌图形；小字号功能标签和手写品牌词使用 `--brand-deepseek-text`，因为现有 `#4D6BFE` 在深色小字场景不足 4.5:1。不要将功能可读性豁免为 logo。品牌图形不通过 CSS filter 反色。

`--border` 是结构线，不承担控件可辨识度。未选复选框、输入框、开关轨道等以 `--control-border` 达到 3:1；disabled 状态用真实 disabled/aria-disabled，不只变淡。错误、未支持和读不到的原因依旧可读。

### 4.1 Element Plus 与主题落地

- 唯一判据仍是 `html.dark`；`:root` 放浅色，`html.dark` 放暗色。不能新增 `data-theme` 或按页面另存主题。
- 几何、字体、行高、圆角、布局只声明一次；dark 块只换颜色/阴影/图像 token。`theme.js` 的默认 dark、light/dark/system、localStorage 键、跨窗口广播和原生窗口作用域不变。
- EP 映射：`--el-bg-color`→surface，`--el-bg-color-page`→canvas，`--el-bg-color-overlay`→surface-raised；text primary/regular/secondary→text/text-secondary/text-muted；placeholder 在浅色→text-muted、深色→text-secondary（JSON的明确值）；disabled→text-disabled；color-primary→accent。
- EP border 系列按结构线映射，但输入框/checkbox/switch 的外框单独用 control-border。`--el-fill-color-blank` 仍 transparent。
- EP primary 的 light-3/5/7/8/9 与 dark-2 不能遗漏：浅色按原 primary 与白色的 30/50/70/80/90% 混合、dark-2 混 20% 黑；深色采用现有明确梯度 `#e7bd69/#9c824f/#6d5e40/#554a35/#2a2114` 与 `#b88b38`。状态色派生档也要在两个主题分别映射，逐一验 hover/pressed/tag/disabled，不能回退默认亮蓝。
- 主按钮文字必须显式读 `--on-accent`，尤其深色黄铜底不能继承白字。secondary 为透明底+控件线，hover 为 overlay-faint；danger 默认文字+浅填，不用整排红色。
- `el-dialog` 自身声明 `--el-dialog-bg-color: var(--surface-raised)`；全屏遮罩读 `--el-mask-color`，局部 loading 遮罩读 `--surface-loading`。不要把两种遮罩合并。
- tooltip 在两主题均用 `--tooltip-*`，浅色不是强制黑块；菜单/select 不套 tooltip 的最大宽规则。所有通过 Teleport 插到 body 的浮层须吃到同一主题。
- 日志、进度、预检、记忆编辑/详情/效果弹窗、确认框、通知和错误兜底都跟主题。不得只适配七个首页。

图表分类色固定使用 tokens.json 的 `--chart-1`…`--chart-8`，模型顺序映射保持现有稳定规则，只将 `usage.js::modelColor` 的硬编码色转为 CSS 变量。磁盘 kernels/instances/stores/logs 分别映射 chart-1/2/3/4；它们是分类，不是健康状态。数字文字仍用 text，图例必须有名称；热力图 0=overlay-faint、1/2/3=heat-1/2/3、4=accent，分位算法不改。危险填色徽标文字用 danger-strong，其他状态文字用对应语义色，按填色合成后验4.5:1。

### 4.2 玻璃只允许在这些地方

允许：标题栏、侧栏底部工具托盘、tooltip/菜单/浮动面板。背景使用 glass-surface（94% 不透明），边界 glass-border，`backdrop-filter: blur(12px)`，阴影 shadow。主分区、表格、输入和行选中态不模糊。

- 不支持 backdrop-filter、降低透明度偏好或高对比环境时，用实色 surface-raised；正文对比度以实色底验证，不能靠背后某张图片保证。
- Windows 原生窗口继续不透明以保留 ClearType；禁止为了玻璃改 Tauri 的平台透明配置。CSS 模糊只采样应用自身背景，不承诺桌面穿透。
- 不做 hover 位移/缩放；颜色过渡 120ms，浮层淡入 100ms；`prefers-reduced-motion: reduce` 下取消非必要动画。

## 5 共享组件和状态

### 5.1 组件落点

先复用 `theme.css` 的 page-head / card-head / page-list / install-row / dialog-actions 与 `PageHeadIcon`、`FamilySwitch`。只有真实复用的结构才抽组件，例如插件目标单元格；不得为七页换皮重写 store、建立第二套 UI 库或复制 bridge。

### 5.2 控件状态表

| 状态 | 显示与交互 |
| --- | --- |
| 默认 | 正文可读、边界明确；可点的元素有 hover 与键盘 focus |
| hover | overlay-faint；行内动作常驻，不因 hover 才能发现 |
| focus-visible | 2px focus-ring，offset 2；不使用 outline: none 无替代 |
| selected | accent-fill + accent 细侧线/明确勾选；不能只靠颜色 |
| pressed | accent-strong（主按钮）或 overlay-soft；无尺寸变化 |
| loading | 保持原宽，spinner + 原动作文案；禁止重复提交；aria-busy |
| disabled | 原因可聚焦查看；真正 disabled；不是用 opacity 伪装 |
| 成功 | 文本说明本次完成的实际动作；保存意图与运行生效分开 |
| 错误 | 当前区域可见错误+重试；仅原 store 允许时保留旧数据并标过期，授权真值不可沿用不可信旧值；不伪装为空 |
| 空 | 说明没有哪类数据、给已存在的下一步；不编造示例数据 |
| 不接入 | **不渲染 MiniMax 复选框**，只留中性「—」；格子在，后面的操作列才不会挪进 MiniMax 列（也不放 tooltip 声称可用） |
| 部分成功 | 显示成功部分和失败部分；回读服务端真值，不把整个动作标成功 |

### 5.3 tooltip 与文案

ⓘ 元素必须可聚焦，`tabindex=0`，aria-label 与提示内容来自同一常量/计算值；hover 与 focus 都能触发，Esc 可关闭。icon-only 按钮保留 title 与 aria-label。禁止嵌套按钮。

可以移入 tooltip：页面介绍、插件具体用途、安装格式、缓存口径、下次启动生效解释、普通流程说明。必须常驻：当前失败及下一步、不接入的「—」、来源/作用范围、需重启短状态、确认前的授权范围、Defender 安全代价、未实现统计来源的标识。

不要把「为了 agent 看懂」「实现机制」「此页面没有…」等面向开发者的说明铺在 UI。必要技术细节在诊断/详情与本开发文档保留，不能通过删提示删除实际能力。

## 7 插件统一列表的完整约束

### 7.1 列表结构

页面由「插件管理」整宽列表 + 「安装插件」整宽分区组成。页头仅标题ⓘ。列表标题右侧保留兼容性检查及自装范围的同步/检查更新入口；若空间不足，工具排另起一行，不能挤掉标题。

表格五列按内容宽 835 的分配：名称及用途 260、状态/版本 minmax(120,1fr)、DeepSeek 104、MiniMax 104、操作 180；各列宽均为包含左右各8px padding的 border-box，不额外叠加 grid-gap，最小总宽768。插件专属断点为内容宽≥768使用五列，≤767采用 §3.2 的两行展示；不得加额外水平padding把总宽再次撑大。

- 同一 `tbody` / 列表中先按后端内置顺序，再按现有自装列表稳定顺序。这里的先后不建立第二标题或第二列表。
- key 为 `builtin:<id>` / `community:<id>`，显示模型仅用于展示和原动作分派；保留两套 store 与生命周期，不能把内置写进自装中央库。
- 插件名后放用途ⓘ；只内置项带 12px「内置」徽标（builtin/builtin-fill），不另加「自装」徽标。
- 行高至少 56；名称行、短状态行可增长。用途不再常驻长段，版本、隔离、错误与实际接入状态保留。
- OpenAI 账号动作有两枚时操作单元格允许两行，行高度自适应。其他已有动作可进有文本的「更多」菜单，不能消失。
- 自装为 0 时只显示内置行，不再出现「暂无自装插件」空框。整个读取失败显示独立错误，不能误报无插件。

### 7.2 当前能力矩阵

| 类型 | DeepSeek 单元格 | MiniMax 单元格 |
| --- | --- | --- |
| OpenAI 内置 | 可操作，requestedEnabled；账号相关动作照旧 | 只读显示「已内置 / 需升级内核」：MiniMax 0.1.7 起自带 Codex 登录，壳没有开关可拨，也不替用户登录 |
| Ponytail 内置 | 可操作，requestedEnabled | 已满足安装/停止/状态要求时可操作；写入意图不等于实机验证完成 |
| 本地记忆内置 | 原内置插件接入开关保留；不得误认为公共池全范围许可 | 记忆页许可的只读镜像，带「在记忆页设置」入口；不是另一个授权开关 |

| 自装插件 | 当前为只读已安装勾选；标「已安装」并说明暂不支持单独停用 | 不渲染控件，只留中性「—」 |

`minimaxPluginTarget()` 为当前判断入口；返回 `null` 的插件**没有 MiniMax 控件**（社区插件与不做适配的内置插件，如 shell-navigation），面板只留中性「—」。图中所有 MiniMax 都可勾选是错误信息。能力由后端/现有 adapter 决定，不能在模板按显示名硬编码。

**逐插件逐内核勾选是展示目标，不意味着可以凭 CSS 创造启停能力。** 自装 DeepSeek 目前没有通用 set_enabled 动作；本轮先忠实呈现只读状态。如果后续要让该格可改，必须单独完成后端启用意图持久化、实例接线、启动应用、运行中限制、错误回读、恢复与测试，再启用交互。取消勾选绝不可调用卸载。MiniMax 任意包适配仍是独立功能，不包含在换皮中。

### 7.3 具体 tooltip 内容

优先使用后端 `displayName` / `summary`；仅在现有 summary 有误时修正文案真值源。不得照搬概念图的错误介绍。

- OpenAI：连接/管理 OpenAI 账号，经授权供相应模型调用；不是「所有服务皆可访问」。保留刷新模型列表、退出登录及真实登录错误。
- Ponytail：复用既有技能与规则能力，说明缺失可选 peer 的降级；**不是模型代理与路由器**。
- 本地记忆：保存、审核、检索注入与记忆页权限入口；插件接入与公共池许可分开说明。
- 官网对话引用：把支持的官网会话内容交给工作台引用；**不是从官网文档搜索内容**。MiniMax 侧暂时停用：官方 WebUI 还不支持工作台式 @ 引用，等上游支持后再移植；面板只读显示暂不支持。
- 自装插件：描述来自其 metadata，若缺少则显示包名/来源，不生成无依据用途。

### 7.4 安装与更新

安装行：输入框 flex 1，按钮 120px，「预检并安装 / 安装」继续由兼容性检查决定；Enter 和按钮同走现有 `installFromSpec`。图中的安装目标双勾选删除，当前安装流程不是一个双内核批量安装 API。

保留预检 `planId`、基线、三态 verdict、报告来源与最终 apply 链路；不能把「预检通过」写成沙盒安全保证。预检关闭后的既有提醒、长进度、失败日志保留，预检报告的取消/关闭按原行为；这不表示普通进度支持取消后端任务。
