# dsh-xlink UI 重设计开发说明

这份文档是 `docs/ui/dsh-xlink-ui-redesign-draft.html` 的实现对照。它说明现有 dsh-xlink 已经有什么、设计稿应该怎样落到真实界面，以及哪些内容暂时不能开发。

实现时以源码行为为准，设计稿只负责表达布局和信息层级。不要为了填满卡片而增加当前版本没有的状态、按钮或统计数据。

## 使用顺序

1. 先读仓库根目录 `AGENTS.md`；改 UI 时读 `ui/AGENTS.md`，改 Rust 或 IPC（进程间通信）时读 `src-tauri/AGENTS.md`。
2. 对照本文件和设计稿确认页面入口、动作归属、状态边界。
3. 在 `ui/src/` 中找到对应组件、store 和动作，再开始修改。
4. 改完先运行 `npm run build:ui`；涉及 Rust 或 IPC（进程间通信）时，按仓库规则补充 Rust 检查。

设计稿的暗色外层背景 token 当前为 `#29272C`。这个颜色只改变主题画布，窗口内部仍保留更深的表面层级。

## 先记住这几条边界

- 这是 Tauri 桌面应用。Vue 页面通过 `ui/src/shell/bridge.js` 调用 Rust，不要在组件里绕过 bridge 直接访问文件、进程或网络。
- 状态和异步动作集中在现有 `ui/src/store.js`、`ui/src/plugins/plugins.js`、`ui/src/skills/skills.js`、`ui/src/shell/progress.js`、`ui/src/logs/logs.js` 与 `ui/src/shell/async.js`。组件负责展示和触发动作，不要复制一套状态。
- 会触发 IO 的按钮必须有 loading 状态。长任务使用现有进度面板，失败后保留原始日志和诊断入口。
- 安装、更新、切换、删除等危险动作必须遵守现有的内核运行状态、实例占用和预检规则。界面不能把禁用条件隐藏掉。
- 插件和技能是两条不同的功能线。插件有按实例接线和沙盒预检；技能目前是技能包管理、逐项启停和手动来源安装。
- 技能社区目录当前没有实现。不要把 GitHub topic 链接画成站内搜索、筛选、排序列表。
- 未配置的套餐服务商继续隐藏。不要为了保持三列或四列而显示虚构的余额和配额。

## 应用外壳

### 顶部内核切换

`ui/src/kernel/KernelTabs.vue` 提供顶部内核族页签。

- 页签按已注册的内核族显示，不能做成 `default⌄` 这样的单一实例下拉框。
- 同一内核族的实例不会在顶部重复显示；实例上下文在页面内容或操作结果中表达。
- 切换页签会切换默认实例并刷新相关状态。
- 没有第二个真实内核族时，不要为了展示多标签硬塞一个虚构名称。

### 侧栏

`ui/src/shell/SideBar.vue` 的页面分组和入口保持稳定：

- 工作台：概览、内核版本
- 资源：插件、技能
- 系统：设置、数据迁移

数据迁移从侧栏「系统」组的常驻入口进入。设置页不再提供重复入口。

品牌区域保留桌面端版本和桌面端更新检查。插件、技能的更新角标只在真实存在待处理状态时显示。

### 窗口行为

- 窗口尺寸固定，不提供用户缩放。
- macOS 使用左侧交通灯；绿色按钮按现有实现不承担普通最大化功能。
- Windows 只显示最小化和关闭，不显示最大化按钮。
- 关闭窗口是收进后台，不是退出进程。真正退出从菜单栏或通知区域菜单发起。
- 恢复、隐藏、登录自启等行为沿用 `src-tauri/src/shell/resident.rs` 和现有事件，不在前端重新实现一套。

## 页面对照

### 1. 概览

主要源码：`ui/src/shell/OverviewPanel.vue`、`ui/src/diagnostics/ControlTower.vue`。

#### 当前内核卡片

卡片表达当前实例和工作台状态，保留以下入口：

- 工作台启动 / 停止
- 官网网页版开关
- 工作台窗口、刷新工作台、官网网页版窗口
- 工作台地址和运行状态
- Node.js 版本；缺失时提供自动安装，已有版本提供重新检测
- 今日用量，打开独立的模型用量窗口
- 当前实例数据目录，打开文件管理器

Node.js 重新检测、模型用量、数据目录打开按钮应分别贴近对应字段，不要集中到卡片底部。

#### 系统健康和操作记录

健康区域对应 `ControlTower` 的真实状态：

- 插件接线：正常或显示被隔离数量
- 技能注册：正常或读取失败
- 日志系统：尚未读取、读取中、读取失败、暂无或日志份数
- 最近快照：暂无或最近快照时间

Node.js 缺失、插件预检失败、工作台故障、设置回退等属于“需要关注”状态，不要伪装成健康列表中的正常值。

最近操作只承载现有的启动、预检、恢复、二分排查记录。没有记录时显示空态；不要添加“日志清理”“插件目录同步”等没有对应运行记录的演示事件。

#### 套餐用量

使用现有服务商顺序和数据语义：

1. DeepSeek：余额、赠金和充值等余额字段。
2. MiniMax-CN
3. MiniMax-EN
4. GLM-CN

后三类按后端返回展示时间窗口和剩余情况。未配置的服务商隐藏。卡片提供全量刷新、详情窗口和单服务商刷新；凭据仍由工作台模型设置维护，壳不保存密钥。

“多币种账户”“剩余配额”不是当前版本的独立功能，不要恢复到界面中。

### 2. 内核版本

主要源码：`ui/src/kernel/VersionsPanel.vue`。

页面包含三类内容：

- 已安装版本：当前版本、其他版本、切换和删除。
- 官方版本：检查更新、打开发布页、安装版本。
- 磁盘用量：只读统计、分类明细、统计时间和重新统计。

切换和删除必须遵守工作台运行状态、另一壳占用和实例共享存储等限制。磁盘用量不能承诺清理功能；读不到的目录要保留错误或不可读状态。

官方版本卡片的标题、最近检查时间和两个图标操作应在同一行，避免标题换行遮住 tooltip（工具提示）。

已安装与官方版本两栏之间使用 2px 竖向刻蚀线，颜色为 `--divider-strong`，上下两端收细。非空时线高跟随已安装列表，空态保留原有居中布局。

### 3. 插件

主要源码：`ui/src/plugins/PluginsPanel.vue`、`ui/src/plugins/plugins.js`。

插件页是一个管理卡片，内部有两个视图：

#### 已安装

- 默认视图，表示全部插件库。
- 每个插件显示来源、版本和各实例的接线状态。
- 接线状态至少要能区分：已接线、已隔离、未同步、版本不一致、未接线和无状态。
- “检查更新”和“同步内核”属于已安装插件的操作，放在已安装功能区的头部。
- 右栏使用「插件中心 / 手动安装」两个页签，默认显示插件中心；切换页签保留搜索条件和手动输入。手动安装支持 npm、git 或现有 `dsh add` 来源格式。右栏标题及两栏分界均使用两端收细的 2px 刻蚀线。「显示更多」位于插件结果滚动区域末尾，滚到最后一条结果后才可见。

#### 当前内核

只显示当前实例的插件管理列表。保留现有动作：

- 同步到当前内核
- 模式切换或复制来源
- 隔离恢复
- 更新
- 打开仓库或来源
- 卸载

这两个视图不能合并成一张含糊的列表。用户需要能看出“所有实例状态”和“当前实例变更”是两种不同操作范围。

#### 插件中心和预检

插件中心来自 `dshfind.com`，当前版本已有查询、分类、排序、详情、安装预检和显示更多结果等能力。手动来源和插件中心安装共用预检开关：

- 默认开启预检时，按钮文案应表达“预检并安装”。
- 用户关闭预检后，文案应明确变为直接安装。
- 预检结果有通过、警告、失败和无法判定等状态。
- 失败或无法判定时不能自动把插件写入当前实例。

插件中心的查询、筛选、排序控件属于已有功能；不要把它们删成只有一个粘贴地址的安装框。

### 4. 技能

主要源码：`ui/src/skills/SkillsPanel.vue`。

技能页目前围绕已安装技能包展开：

- 显示包来源、版本、描述和 copy / link 模式。
- 显示包内技能，并支持逐项启用和停用。
- 保留条目缺失提示、本地重新同步、更新、仓库链接和卸载。
- 遇到更高优先级目录遮蔽或条目冲突时，提供“移走”处理。该动作改名并保留源文件，不做静默删除。
- 社区区域只提供 GitHub `dsh-skill` topic 浏览。
- 手动安装支持 GitHub 地址、`owner/repo` 简写和 tag 来源，安装后回到已安装区域管理。技能社区与手动安装之间使用一道 2px 刻蚀线，颜色为 `--divider-strong`，两端收细。

当前没有站内技能社区目录、技能搜索、技能排序或技能详情安装列表。设计稿中不能出现虚构的社区技能卡片、星标数量和“详情”按钮。

### 5. 设置

主要源码：`ui/src/shell/SettingsPanel.vue`、`ui/src/diagnostics/SnapshotCard.vue`、`ui/src/diagnostics/BisectPanel.vue`。

设置页至少保留以下区域：

- 工作台 Web UI 端口和保存配置。
- 关闭窗口后留在后台的固定行为说明。
- 系统登录时启动管理台。
- 登录后自动启动工作台。
- 任务完成通知、仅后台通知、通知声音和试听。
- 未读数量、通知记录和最近完成记录。
- 环境回退点：查看、验证和恢复。
- 深入排查：开始、继续或停止二分排查。
- 启动诊断入口。
- 数据迁移入口位于侧栏，设置页不再重复提供。

保存配置是当前工作台 / 当前实例的设置动作，应靠近工作台标题和当前实例上下文。不要把它放到页面最右上角，造成它像全局主题设置。

环境回退与诊断的行间分隔使用 2px 蚀刻线，颜色为 `--divider-strong`，两端收细；最后一行下方不画线。

### 6. 数据迁移

主要源码：`ui/src/migration/MigrationPanel.vue`、`ui/src/migration/MigrationPrompt.vue`。

迁移页是四步向导：

1. 发现：扫描来源、旧路径、新路径、文件数和大小。
2. 选择：选择来源，并确认冲突策略。
3. 运行：显示选中的来源、备份位置和当前进度。
4. 完成：展示复制、跳过、备份和错误结果。

还要保留：

- 迁移历史和回滚。
- 重新扫描、再次询问迁移。
- 找回其他实例中的历史会话或附件。
- 找回操作只复制，不删除来源，不覆盖目标已有条目。
- 凭据和会话附件不进入普通迁移范围。

迁移卡片不能只写“插件库 / 技能库可迁移”，那会丢掉来源选择、冲突策略和结果报告。

## 独立窗口、弹窗和异常态

这些不是可有可无的装饰。它们由 `ui/src/App.vue` 和对应模块挂载，开发时要保留入口及关闭路径：

| 能力 | 入口或组件 | 开发要求 |
| --- | --- | --- |
| 模型用量 | `ui/src/usage/UsageWindow.vue` | 保留今日、7 / 15 / 30 / 60 / 90 天范围，以及 token 汇总和趋势信息 |
| 套餐用量 | `ui/src/subscription/SubscriptionWindow.vue` | 按服务商显示配置状态、刷新、错误和前往模型设置；未配置服务商隐藏 |
| 官网对话 | `ui/src/official-chat/OfficialChatTabs.vue` | 保留 DeepSeek / MiniMax 页签和独立窗口行为 |
| 日志查看 | `ui/src/logs/LogModal.vue` | 保留刷新、折叠侧栏和独立日志窗口入口 |
| 长任务进度 | `ui/src/shell/ProgressOverlay.vue` | 失败时保留诊断和原始日志路径，不能自动关闭失败面板 |
| 插件预检 | `ui/src/plugins/PrecheckDialog.vue` | 通过、警告、失败、无法判定都要有明确的下一步 |
| 启动故障 | `ui/src/incidents/IncidentModal.vue` | 能查看诊断、日志、证据和可疑项，并执行恢复或清理 |
| 诊断页面 | `ui/src/diagnostics/DiagnosisShell.vue` | 覆盖启动、内核、插件、恢复和二分排查，保留刷新和返回 |
| 环境回退 | `ui/src/diagnostics/SnapshotRestoreDialog.vue` / `ui/src/diagnostics/SnapshotCard.vue` | 恢复前预检，恢复后验证；恢复只处理已有的插件 / 技能状态 |
| 迁移提示 | `ui/src/migration/MigrationPrompt.vue` | 首次发现旧数据时提供确认和再次打开入口 |

设计稿主预览不需要把每个窗口全部展开，但功能清单和页面入口不能删掉。实现时先找现有组件，不要重新造一套弹窗状态。

## 不能从设计稿推断出的内容

以下内容不能因为视觉上需要填充而直接加入：

- 多币种账户、独立剩余配额卡片。
- 当前版本不存在的工作台重启按钮。
- 技能社区站内目录和虚构的社区技能数据。
- 未在后端返回的余额、百分比、更新时间、星标数量或插件数量。
- Windows 最大化按钮。
- 内核目录内的补丁写入、运行时篡改或额外清理动作。
- 通过环境变量臆测内核支持的接线方式。

遇到确实有价值、但源码尚未支持的想法，先放到候选计划，不要混入当前实现。

## 候选计划

这些方向暂不属于当前版本 UI：

1. 技能社区目录：缓存、查询、筛选、排序、详情和安装。
2. 按实例覆盖技能启用状态。
3. 从系统通知直接定位到具体会话。

进入开发前需要单独确认数据来源、权限边界和持久化方式。没有确认前，只保留设计记录。

## 实现验收清单

提交 UI 改动前逐项确认：

- [ ] 浅色、暗色、macOS、Windows 和收起侧栏均能渲染。
- [ ] 暗色背景为 `#29272C`，卡片、侧栏和标题栏仍有清楚层级。
- [ ] 页面不出现额外的纵向滚动条，固定窗口内的内容不被裁切。
- [ ] 所有 IO 按钮有 loading，长任务有进度和失败诊断。
- [ ] 插件已安装 / 当前内核两个范围没有混淆。
- [ ] 技能页没有伪造社区目录，遮蔽和冲突处理入口仍在。
- [ ] 设置页的常驻、通知、快照和二分排查入口仍在；迁移入口保留在侧栏。
- [ ] 首次运行、无 Node.js、插件隔离、预检失败、迁移冲突和无配置服务商等状态有对应空态或异常态。
- [ ] 运行 `npm run build:ui`；涉及 Rust 或 IPC 时再运行仓库要求的检查。

### 外观设置

设置页右栏提供浅色、深色、跟随系统三个带图标的选项，点击立即生效并记住选择。侧栏底部用太阳、月亮、显示器表示当前模式，点击打开三项快捷菜单。跟随系统先解除原生外观覆盖，再读取系统配色并响应后续变化；固定浅色或深色不受影响。页面、弹层及已打开的壳副窗口统一使用解析后的配色，旧用户默认与已有选择保持不变。
